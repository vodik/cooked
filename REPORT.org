* Why this document

[[file:../ghostel][ghostel]] is an Emacs terminal emulator over =libghostty-vt=, the VT engine
behind Ghostty: Zig core, ~21.8k lines, on MELPA, with a prebuilt module that
auto-downloads. cooked is a Rust core with a vendored vte, ~41.3k lines counting
tests and docs, built from source.

Both are young, and ghostel is more mature in shipped surface area. It is also
faster on raw throughput today, and closing that needs work in the parse loop
rather than in the architecture — cooked's per-drain marshalling is *cheaper*
than ghostel's per-redraw property application, so the gap is libghostty-vt's
parse rate against the vendored vte, not the shape of the design.

*Two caveats on that, both worth stating before any number below is read as a
verdict.*

*The throughput benchmark rewards unbounded buffering.* ghostel drains the pty
as fast as the kernel supplies and buffers *events* without limit; cooked
deliberately stops reading at =backlog_limit= and blocks the child in =write=.
A =time cat bigfile= therefore scores cooked's better behaviour worse.
ghostel's README makes exactly this argument against vterm and eat — that the
wall clock hides a frozen main thread — and the same argument cuts the other way
here along a different axis: ghostel stays responsive *and* unbounded, cooked
stays responsive *and* bounded. At roughly 90 MB/s ghostel is also close enough
to a pty's practical ceiling that the headroom for cooked to lose is limited.

*On interactivity the bet plausibly runs the other way, and ghostel's own source
is the evidence.* =ghostel-bench-typing-latency='s docstring names the one place
the backend ordering *inverts* relative to throughput: the native path's
background-thread read signals Emacs through an event pipe, so a single tiny echo
carries an extra IPC hop the main-thread filter does not pay. Per keystroke,
cooked sends one byte and drains on Emacs' schedule where ghostel formats Lisp
source text into a pipe and =eval=s it; cooked jumps to the damaged row where
ghostel funcalls =eobp=/=point=/=forward-line=/=point= for every row on screen;
cooked hits a memoized face cache where ghostel builds a fresh plist with fresh
=#rrggbb= strings. And ghostel's 33 ms coalescing timer *needs* a 0.05 s
immediate-redraw bypass to not feel bad — an exception cooked's model never
required, because it was never a clock.

Two things could spoil that. One is latency in a *decorated* buffer, where cooked
would lose: per-character =display= properties and jit-lock link scanning with
=mouse-face= overlays all land inside the redisplay cycle for the echoed row.

The other was checked in the tree, and the answer is worth recording.
*=interacted_until= relaxes neither pacing gate.* It appears in exactly one
place — =base_poll_wait= (=session.rs:1159=), choosing =POLL_TIMEOUT_MS= (100 ms)
over =UNATTENDED_POLL_TIMEOUT= (1000 ms), and only while the session is
*unattended*. =Notifier::flush= never consults it. Its real job is waking a
sleeping reader off a one-second poll on the first notch of a gesture, and
=interacted()= returns early when =attended= is set, so an attended session gets
nothing from it. So a keystroke echo pays:

- *Quiescence: ~500 µs, unconditionally.* The read that delivered the echo just
  refreshed =last_read=, so =hold()= returns =Some(~500µs)=; =poll_wait=
  shortens the poll to that window and the frame is drawn ~500 µs later. Below
  perceptual threshold, and it is the same mechanism that prevents tearing —
  leave it alone.
- *=min_interval=: 8 ms, conditionally.* =state.last= is when a wake byte last
  went out, which at an idle prompt is stale — so the floor does not engage and
  an isolated keystroke costs the 500 µs and nothing else. It engages when
  typing *into active output*: answering a prompt mid-build, typing at a shell
  while a background job writes, a TUI repainting underneath.

That mixed case is the one real exposure, and it is precisely where ghostel's
0.05 s bypass wins — they special-case keystrokes out of their pacing model and
cooked has no interaction-aware path on the redisplay side at all. The minimal
answer is to let a live interaction window impose a *shorter floor* rather than
skip the check, keeping the property that =rearm=-vs-=ready= exists to protect:
a floor that is bypassed during typing while the child is also flooding is a
floor that never engages.

*Neither project has a head-to-head number, and that is the real gap.* §9
recommends skipping the cross-emulator throughput harness as marketing — but a
=typing/*= comparison is not marketing, it is the one measurement that would
settle this.

There is room for both regardless: cooked's bet is *comint composition* — being
a real Emacs buffer that composes with Emacs machinery — and nothing in ghostel
threatens that bet. The interesting finding of this survey is that the bet is
currently only *half* collected.

This is a survey for borrowing, not a scorecard. Each section ends with what
cooked does better, because several of those are load-bearing design arguments
that should not be traded away for a feature.

Note on line counts: they mislead on this axis. =evil-ghostel= is 1025 lines to
=cooked-evil='s 568 and most of the difference is *machinery cooked does not
need*, not features cooked lacks. Same for =ghostel-line-mode.el=. Read §5
before drawing a conclusion from a =wc -l=.

* What cooked does better

ghostel is ahead on shipped surface area. cooked is ahead on the things that are
expensive to retrofit. This section consolidates what the eight axis surveys
found; each axis section below keeps its own detail.

Read it as a list of *arguments already won* — the shortlist that follows asks
cooked to give up almost none of them.

** The bet nobody else made

=cooked-mode= genuinely =define-derived-mode='s from =comint-mode=
(=cooked-mode.el:1718=): a real =process-mark=, a real =comint-input-ring= fed
by =cooked--history-record=, real =comint-last-input-start/end= maintained across
grid rewrites, and =comint-get-old-input= answered from OSC 133 records rather
than a prompt regexp. ghostel's terminal buffer is standalone and borrows comint
only for completion plumbing; its comint work goes *outward* to decorate other
people's buffers. Those are complementary, which is why §1 is a gap and not a
weakness.

Everything downstream follows from one consequence: *the input line is Emacs
text.* So undo, Quail/IME, =completion-at-point=, kill/yank, isearch and evil's
stock operators all work with no reimplementation. =evil-ghostel='s extra 450
lines — PTY-driven operators clamping to the input region, cursor driving by
arrow keys with an =accept-process-output= settle loop, autosuggestion detection
by reading a cell's foreground for dimness and low saturation — exist only
because the shell always owns the line there.

** The module boundary

cooked's wire protocol has no counterpart on the other side:

- *22-byte fixed-stride style records* (=src/lib.rs:930=) walked with =aref= — no
  cons per span, no cons for colours, no cons for the cache key. 1.20 → 1.03
  ms/frame, ~1500–2300 fewer cons cells per frame.
- *Run-length-encoded glyph decorations*: an 80-cell border row is one record,
  not eighty. 9.5 → 2.8 ms/frame.
- *Row geometry carried, not measured* (=Run::cols= + the ASCII flag), replacing
  a per-row =string-width= that cost 49.5 µs ASCII / 113.5 µs CJK / *545 µs box
  drawing*.
- *A face cache memoized on the packed bytes* (=cooked-face.el:230=); truecolor
  14.6 µs → 2.6 µs.

ghostel rebuilds a face plist — including =env.makeString("#rrggbb")= per colour
— per run, per redraw, with no cache anywhere (=style_face.zig:135=).

Images are the same story at larger scale. cooked: pixel bytes cross *once,
ever*, per distinct image; steady state with a picture on screen is *zero bytes*
plus a 12-byte placement record per cell. ghostel re-converts to PPM, re-copies
into a fresh Emacs string and re-=create-image=s *per placement per redraw* — a
1920×1080 placement is ~6 MB of allocation, ~6 MB of memcpy and a spec hash over
~6 MB on every redraw that dirties any row. Emacs' =image-cache= saves the
decode, not the conversion, the copy or the hash.

And *content-addressed identity*: a 128-bit digest means a program redrawing the
same picture every frame costs one decode, and a client reusing its own =i== for
a different picture cannot make two images alias. ghostel keys on the client's
=image_id= and inherits both problems.

Links likewise: a 4-byte =LinkId= per cell, one =(ID . URI)= transfer per
distinct destination, and =help-echo= as a *lazily-evaluated function* — against
re-marshalling the whole URI string into =help-echo= on every repainted run. With
a full-URI compare behind the hash bucket and a planted-collision test
(=a_shared_hash_bucket_does_not_alias_a_different_uri=) closing a real
destination-spoofing hole.

** Pacing, process, and the seam

- *Four gates with Emacs' own completion as the retirement signal*
  (=session.rs:424=), against a 33 ms timer plus =adaptive-fps= plus a keystroke
  bypass — three tuning knobs approximating what cooked gets for free. Measured:
  40 applies against 91 redisplays under a =yes= flood, so renders never outrun
  redisplays.
- *DEC 2026 with a 150 ms deadline*, sharing one number with =HOLD_CEILING= so
  there is a single answer to "how long may anything hold the buffer still".
  ghostel's =redraw= returns early whenever the mode is set, *with no timeout* —
  a child that never resets it freezes the display.
- *Real backpressure*: the reader stops =read(2)=ing at =backlog_limit=, the pty
  fills, the child blocks in =write=. ghostel buffers *events* rather than
  throttling *input*, so memory is unbounded under a flood.
- *The wake protocol is a token, not a message* — one byte, not re-armed until
  Emacs acknowledges by draining. ghostel serializes Lisp *source text* into a
  pipe and =eval=s it (=NativeProcess.zig:176-232=): more allocation, a larger
  attack surface, and no natural place to put backpressure.
- *Resize confirmed by tty read-back*, because a child's own init can overwrite a
  successful =TIOCSWINSZ= invisibly. ghostel fires the ioctl and swallows
  =EIO/ENXIO=.
- *Reaping race-free by construction* — a =reaped= flag and its mutex serialize
  =killpg= against =waitpid= so a recycled pid is never signalled. ghostel's
  sentinel =signal-process=es unguarded.
- *Job control read from termios*, so =stty intr ^X= works. No ghostel analogue.
- *The seam is one co-owned number with a debug assertion* (=cooked--check-seam=),
  where ghostel detects =CSI 3 J= by an =offset+len==total= snap-back heuristic.
- *One PTY path, and it is the strong one* — no =use-native-pty= flag, no second
  write path, no =backend_handoff_mutex= guarding a backend one path can retire
  while another blocks writing to it.

** Safety as a house style, not a feature

*Every query that can be answered is answered — including the refusals.*
XTSMGRAPHICS declines with the protocol's own status codes; kitty graphics
decline with =ENOTSUPPORTED:<reason>= honouring =q=1/q=2=; and *DECRQM answers
4 "permanently reset"* for modes deliberately unimplemented, so the terminfo
claim is machine-auditable. ghostel's "unsupported" is mostly silence, and
silence is what hangs clients. (Its one Elisp-layer refusal, source-rect crops,
signals an Emacs error that never reaches the client at all.)

*One reply framer with one rule*: =reply_safe= rejects any payload carrying a C0
control or DEL, applied uniformly by =csi_reply=, =dcs_reply=, =osc_reply= and
=apc_reply=, dropping a refused reply whole rather than truncating. No
equivalent choke point exists on ghostel's side.

*The eval channel is a closed verb set behind a =require=*, with the escape
hatch's table empty by default, each verb validating its own argument, and
dispatch *deferred out of the drain*. ghostel allowlists *function names* —
which settles which function runs and says nothing about what it is pointed at —
ships =find-file= by default, and applies it synchronously *inside the VT
parser*. =ghostel_cmd find-file /ssh:attacker.example:/etc/motd= is a TRAMP
connection to a sender-chosen host, reachable from any =cat= of a hostile file,
with no opt-in anywhere.

*Refusing to guess on another host*: OSC 7 declines a foreign authority with the
argument written down, and refuses TRAMP names *before* =file-directory-p= so a
hostile stream cannot make the handler itself open a connection.

*Hostile-input bounds, each individually justified* (=docs/IMAGES.md=):
geometry-vs-payload amplification capped at 2×, =MAX_IMAGE_CELL_SPAN= so one
small PNG cannot force 65535 linefeeds, =sixel::MAX_PIXELS= because =!= is a
compressor, =IMAGE_BACKLOG_UNIT= so pictures are visible to backpressure written
for rows.

*Notifications*: off by default, rate-limited 3/10 s, length-capped
(title 120 / body 500), control characters stripped, and chunked OSC 99 =d=0=
reassembly bounded on both open-notification count and accumulated text.
ghostel hands raw child-controlled title and body to =alert= with no cap, no
rate limit and no sanitisation, on by default.

*Secret handling under divided attention* — the single most important
correctness property in that area, and ghostel has nothing like it. If
=cooked--attention= is =away= the read is *held* and only a message shown,
because =read-passwd= takes the selected frame's minibuffer: otherwise the next
keys the user types in an unrelated buffer go to this child, followed by a
newline. Plus the epoch counter, so a stale answer is refused and a stale quit
cannot =C-c= whatever is running now. And =README.md='s "On passwords" states
the heap/GC/auth-source limit plainly rather than claiming the secret leaves no
trace.

** Refusal discipline in the small

=cooked-evil-visual-case= and =cooked-evil--command-range= *return or message
rather than signal*, with the reason written down: a signal skips
=post-command-hook=, leaves evil believing in an invisible visual state, and the
next =v= then /exits/ visual. =cooked-evil-undo= reports "No further undo
information" instead of leaking "Buffer is read-only". That class of care is not
present on the ghostel side.

** Things ghostel does not have at all

- *Sixel* — absent from ghostel and from libghostty-vt entirely (the only
  occurrence in the vendored tree is the DA1 enum value =sixel = 4=). cooked's is
  a 524-line two-pass decoder verified pixel-for-pixel against =sixel2png= across
  six colour/dither settings up to 2000×1000 including alpha.
- *OSC 66 text sizing* — the protocol-level fix for the entire cell-disagreement
  problem.
- *Box-drawing glyph rasterization* — ghostel has no glyph renderer;
  =GlyphMetricsCache.zig= is a font-metrics cache. Plus the two traps cooked
  documented with the defects that found them (colouring the bitmap breaks
  =hl-line=/region/=isearch= compositing; =solaire-mode='s =create-image= advice
  recolours everything except borders).
- *modifyOtherKeys* (zero references in ghostel), *19 keypad terminfo caps* with
  NumLock dual spelling (ghostel binds no keypad key), *DEC 1007 alternate
  scroll* so the wheel works in =less/man/git log*, and =backtab='s classical
  =kcbt= fallback.
- *Per-program key policy* — =cooked-key-protocol-overrides= /
  =cooked-key-overrides=, a real answer to programs that assume kitty without
  negotiating.
- *Frame-type-aware Meta handling*, chosen at map-install time, so terminal
  frames never pay ESC latency. vterm, eat and ghostel all pay it
  unconditionally.
- *Real zsh compsys and bash completion from the live shell* over =OSC 51;C=,
  with descriptions and groups, nonce-authenticated per ZLE line. ghostel uses
  =bash-completion.el='s hidden subprocess — the route ROADMAP §1 considered and
  rejected — and only in line mode.
- *The only genuine request/reply Elisp channel*, versioned, with a documented
  capability field for older snippets.
- *Per-command records* (=cl-defstruct cooked-command=, with the reasoning for
  each anchor choice written down) and the fringe decorations, rerun,
  copy-command, copy-output and write-output built on them. ghostel keeps
  =(line . exit-status)= pairs and has none of it.
- *=cooked--ownership-license=* (=cooked.el:631-663=) — genuinely original, and
  the framework that makes remote safe: an OSC 133 =B= is byte-transparent, which
  is what makes it survive an =ssh= and also what stops it corroborating itself,
  so the line is lifted into Emacs only when something else backs the claim — and
  the transport is *not* the license.
- *Mark semantics as a specification* (=FEATURES.md:195-275=): the =k== table
  with =r=-or-unknown dropped whole and the session-ending-bug reason why, plus a
  six-row duplicate/missing-mark table.
- *Frame shedding* (=state.rs:260=) — 61 MB → 8 MB at 8 frames/drain.
- *Reaching into Emacs' own image cache on eviction* (=cooked-deco.el:711=), the
  layered-cache disagreement nobody thinks about until an animation leaves
  thousands of rasters resident for five minutes.
- *A streaming grapheme segmenter* conformant to kitty's text-sizing algorithm,
  correct across =read(2)= boundaries, with its one disagreement with
  =unicode-width= stated outright.
- *A four-face, 27-ligature fixed-pitch probe* — which found that ligatures are
  *not* the alignment hazard (0 of 27 misrendered across four monospace fonts)
  and proportional faces are. ghostel's coverage probe starts at U+00FF, so ASCII
  in a proportional face produces silent drift it cannot see.
- *Stamp-based invalidation over notification* (=cooked.el:1673=) — a stamp
  cannot miss an event it was not told about; ghostel's cache flushes only on
  default-font change and would not notice a fringe or margin change.
- *Per-cell image placement as semantics*: text overwriting part of a picture
  leaves the rest, a scroll splits it across the screen/scrollback seam, a rewrap
  moves it with its columns — all free, because there is nothing to carry but
  text properties. Plus source rects, cropping and rescale with no
  retransmission, where ghostel refuses crops outright.
- *Three image protocols* (kitty + sixel + iTerm2 =OSC 1337=) converging on one
  pipeline downstream of "here are some pixels".
- *=cooked-tests-bench.el=* — ERT tests pointed at the *benchmark's own
  fixtures*, written because both had already gone stale once and "a fixture that
  goes wrong more quietly would simply have reported a plausible number for work
  the renderer never does". The bench survey called this cooked's best
  benchmarking idea and said ghostel should copy it.

** The meta one

cooked's docs argue trade-offs; ghostel's document usage. =docs/DESIGN.md= and
=docs/KEYBOARD.md= say why TAB cannot simply be forwarded, why a mark alone is
not a license, why =C-y= is never an exception, why =raw= and =alt= get
different defaults, and why =grep-mode= is excluded *as an instance of a rule*
rather than as a special case. Three separate axis surveys independently
concluded that cooked's reasoning-about-measurement is better than anything on
ghostel's side — including the =cooked-bench.el= commentary that explicitly
refuses to let its own RATIO=8 figure be read as a claim about a live session,
and cites the 40-applies-per-91-redisplays measurement to say why.

Several of cooked's best decisions are recorded as *a bug found and written
down* — the =compilation-sentinel= double-annotation under a still-active
=cl-letf=, the =or=-arm that made the row guard unconditional on graphical
frames, the =%%%= padding case Ghostty's own test gets wrong, =_git='s
=compadd -O= probes arriving as duplicate candidates. That record is the asset
that does not show up in a feature matrix.

** The honest counterweight

ghostel has roughly 480 tests on the input axis alone against cooked's 169; it
is on MELPA with an auto-downloading prebuilt module; and it ships TRAMP remote
terminals, progress reporting, IME, drag-and-drop, yank-media, a buffer picker
with annotations and a public Lisp API. That is real maturity — and it is mostly
*additive*, which is why the shortlist below runs to 37 items and almost none of
them ask cooked to trade away an argument it has already won.

* 1. The comint filter — the top item
:PROPERTIES:
:AXIS: process model, module boundary, Emacs composition
:END:

** What ghostel built

=src/comint_filter.zig= (436 ln) + =lisp/ghostel-comint.el= (200 ln). A
=gt.Stream(Handler)= with *no Terminal and no grid* — a pure
byte→propertized-string transformer. =ghostel-comint-global-mode= puts it on
=comint-preoutput-filter-functions=, so *every* comint buffer in Emacs gets a
real VT parser instead of =ansi-color-process-output=.

Three things in the design are worth taking whole:

1. *The hook choice sidesteps comint's marker semantics entirely.*
   =comint-preoutput-filter-functions= is a string→string hook. The filter never
   touches the buffer, never moves =process-mark=, never interacts with
   =comint-last-input-end=, field boundaries, or =comint-move-point-for-output=.
   comint does all insertion afterwards, exactly as it always did.

2. *Partial escape sequences across chunks are free*, because libghostty's
   =Stream= is itself a resumable state machine. A =feed= ending mid-CSI leaves
   the parser parked; the next =feed= continues it. Nothing buffers a partial
   escape by hand. This is the entire reason to own a VT parser rather than a
   regexp, and it is the argument for cooked doing this at all.

3. *Runs are tracked by character offset, not byte* (=comint_filter.zig:28-31=),
   because =put-text-property= on a multibyte Emacs string takes character
   indices. Byte offsets corrupt or error.

Cumulative =gt.Style= persists across =feed= calls, so a =\e[31m= in chunk /n/
colours text in chunk /n+1/ (they have a test named for it). OSC 7 calls back
into Lisp mid-feed with an explicit =nonLocalExitCheck/Clear= so a signalling
Elisp callback cannot poison the rest of the feed — that gives =M-x shell=
directory tracking with no =shell-dirtrack-mode=.

** The bug ghostel ships, which cooked already documented

=cooked-process.el:28-42= states it exactly:

#+begin_example
  $ printf 'abcdefghij\rXYZ\n'
  XYZ           # comint: the CR deleted to the start of the line
  XYZdefghij    # correct: the CR moved the cursor and XYZ overwrote
#+end_example

ghostel is the first line. It passes CR/BS/TAB/BEL through as raw bytes for
=comint-carriage-motion= and silently drops erase-in-line, cursor addressing,
alt-screen and scroll regions (=comint_filter.zig:263=, the =else => {}= arm).
Passing CR through means comint *deletes* to BOL rather than *overwriting*, and
because CSI K is dropped there is nothing left to distinguish "child erased the
line then reprinted" from "child rewrote part of it". Progress bars usually
survive by accident; partial overwrites do not.

** Design sketch for cooked

Do *not* copy ghostel's grid-less handler wholesale, and do *not* reuse
=cooked-process.el='s headless grid. The grid is wrong here for a concrete
reason: retirement latency. =cooked-process-rows= is 8, so nothing reaches the
consumer until the 9th line — fine for =compile=, fatal for =M-x shell=, where
you would sit eight lines behind your own prompt.

A third mode of the parser, between the two.

*Rust side — =src/emu/stream.rs=, a new =Perform= impl (~200–250 ln):*

#+begin_src rust
/// SGR and OSC-8 state across chunks, with no grid behind it.
pub struct Filter {
    parser: parser::Parser,      // vendored vte, already resumable
    style: Style,                // cumulative; survives feed()
    underline: Color,
    link: Option<LinkId>,        // reuse emu::link::LinkStore
    text: String,
    runs: Vec<Run>,              // exactly emu::cell::Run
    pending: usize,              // char offset of open run
}
impl Filter {
    pub fn feed(&mut self, bytes: &[u8]) -> (&str, &[Run]);
}
#+end_src

Four things make this cheap in cooked specifically:

- The parser is already resumable and already vendored. A second =Perform= impl
  is the sanctioned extension point; =term/perform.rs= is the existing one at
  ~231 lines, most of which is grid work a stream filter skips.
- =Run= and =Style= already exist (=emu/cell.rs:374=, re-exported at
  =emu/mod.rs:132=) and are exactly the right shape. Factor the =set_attribute=
  arm out of =term/csi.rs= so grid and stream share SGR decoding — the same move
  ghostel made with =style_face.zig=.
- *=Block::push_style= is already the wire format*, and it is strictly better
  than ghostel's approach. =src/lib.rs:930= packs a run into 22 bytes;
  =cooked--render-block= decodes it with a face cache memoized on the packed
  bytes (=cooked--face-packed=). Zero allocation per span, one face lookup per
  distinct rendition per buffer, and the same face objects the terminal uses.
  ghostel calls =put-text-property= from Zig, once per run per property.
- OSC 7 already has a Lisp handler (=cooked-osc.el:544=) doing TRAMP/hostname
  resolution. Route the filter's OSC 7 through it; do not write a second one.

*The one real decision — CR/BS/erase.* Two options:

- (a) Pass through like ghostel. Cheap, wrong, and cooked's own docs say so.
- (b) Resolve them in a one-row line buffer. Keep a =Vec<Cell>= of the current
  logical line only. CR sets column 0; BS decrements; =CSI K= truncates; =\n=
  retires the line to =text= and clears. No scroll region, no cursor addressing,
  no height — *so no retirement latency*, because a line retires the moment its
  =\n= arrives.

Take (b). ~60 lines over (a), correct overwrite semantics, and it makes the
filter strictly better than =ansi-color=, =xterm-color= /and/ ghostel. It also
lets =cooked-comint-mode= drop =comint-carriage-motion= from
=comint-output-filter-functions= — one fewer pass over every chunk.

The detail to get right: a line must retire on =\n= *and* whenever =feed= ends
with a partial line, so an unterminated prompt (=read -p=) shows up immediately.
Emit the partial line and remember how many characters were handed over, so the
next =feed= re-emits only the delta. That is a =head=-style continuation count,
the same mechanism =Update::scrolled_rows= already uses (=cooked-process.el:513=
reads =:head= for it).

*Lisp side — =lisp/cooked-comint.el= (~150 ln).* Sits on =cooked-util.el= +
=cooked-face.el= only; must not require =cooked.el= (no session, no grid, no
keymap). Per =docs/DESIGN.md:629= this is a /sibling/ of =cooked-process.el=,
not a layer.

Two deliberate divergences from ghostel:

- *Set both =face= and =font-lock-face= unconditionally, to the same value.*
  =cooked-process.el:350-358= already argues this out and is right. ghostel
  renames =face=→=font-lock-face= conditionally on =font-lock-mode= /at filter
  time/ (=ghostel-comint.el:90=), so text emitted before the user enables
  font-lock gets stripped on the next fontify. Setting both costs one extra
  property interval and is correct under every ordering, because
  =char-property-alias-alist= is consulted only where =face= is absent.
- *Drop decorations, and either re-scope links or emit the URI directly.*
  =cooked-process--text:325= already explains why: a =cooked-link-id= resolves
  through the /session's/ buffer-local =cooked--link-uris=, and there is no
  session here. Emitting the URI as =help-echo= is simpler and loses nothing
  that matters in a shell buffer.

Ship =cooked-comint-mode= (buffer-local) and =cooked-comint-global-mode=. Copy
=ghostel-comint.el:177='s buffer-list sweep verbatim — it is the right shape —
including the non-obvious bit at =:161-166=: when a global mode enables a local
mode in /pre-existing/ buffers, =global-eldoc-mode='s auto-enable has already
run, so the local mode must call =(eldoc-mode 1)= itself. Remove
=ansi-color-process-output= from =comint-output-filter-functions= on enable;
do not re-add on disable (ghostel's choice, and correct).

** Why this is the top item

cooked's thesis is comint composition, and right now that thesis is proven only
for *cooked's own buffer*. =cooked-comint-mode= extends it to every comint
buffer in Emacs — =M-x shell=, =run-python=, =sql-interactive-mode=,
=inferior-ess=, =gud= — a large surface where the alternatives (=ansi-color=,
=xterm-color=) are all regexp-based and all wrong on the same cases. It is also
the only item in this survey with a plausible "why cooked and not vterm" answer
for users who will never open a full terminal.

Note the direction of travel: ghostel's comint work goes /outward/ to other
buffers while its own terminal buffer is standalone; cooked's goes /inward/ —
=cooked-mode= actually =define-derived-mode='s from =comint-mode=
(=cooked-mode.el:1718=), with a real =process-mark=, a real
=comint-input-ring=, real =comint-last-input-start/end= maintained across grid
rewrites, and =comint-get-old-input= answered from OSC 133 records instead of a
prompt regexp. Those are complementary, which is why this is a gap and not a
weakness.

* 2. The scroll ceiling, and where the 20x actually goes
:PROPERTIES:
:AXIS: images, glyphs, caching, IPC
:END:

** The mechanism, confirmed

ghostel puts *one =display= property per image row, spanning the whole column
range*. cooked puts *one per character*. For a 60×20-cell image that is 20
intervals versus 1200 — each of cooked's freshly consed
(=cooked-deco.el:1007=), plus 1200 =cooked-deco= properties.

The existing profile localises it exactly: =find_interval= 15%,
=parse_image_spec= 12%, =validate_interval_range= 10%, and *no image-drawing
symbol at all*. A distinct =display= property per char is 47% of the budget; it
being an image is 51%; pixels are ~0. ghostel does not pay it because redisplay
walks 20 intervals and parses 20 specs, and because the spec within a row is
shared by every character in the range — so =parse_image_spec= runs once per
interval rather than once per column.

The whole trick is =ghostel--kitty-apply-row-slice= (=ghostel-kitty.el:99-144=):

#+begin_src elisp
(add-text-properties start end (list 'display spec 'ghostel-kitty t))
;; spec = ((slice slice-x (* row ch) clamped-slice-w ch) img)
;; [start,end) spans the placement's whole column range on that buffer line
#+end_src

Importantly, *the merge hazard cooked documents does not apply here.*
=cooked-deco.el:876-900= and the test
=cooked-adjacent-box-glyphs-do-not-share-a-display-property= guard against
Emacs collapsing adjacent identical specs. ghostel's per-row spec is sized to
exactly the cell range it covers, so Emacs merging that interval into one
displayed image is the /intended/ behaviour: it draws one 60-cell-wide slice
occupying precisely 60 cells.

** Why cooked cannot just copy it, and what to do instead

Per-cell addressing is not an accident — it is what makes text-overwrites-part-
of-a-picture, scroll-splits-across-the-seam, and rewrap all work for free
(=src/emu/image.rs:~150=). Any fix must preserve that.

The honest shape is a *hybrid*: coalesce runs of cells that are contiguous,
same-image, same-rectangle and same-slice-row into one interval — which is the
common case, a freshly drawn picture — and fall back to per-cell only where the
grid has actually broken the run. The core already knows the runs; this is the
same run-length insight =Deco::packed= uses for glyphs.

Wire format consequence: the 12-byte-per-character image record at
=src/lib.rs:1137= becomes a per-row-run record
=(id, crow, start-col, ncols, cols, rows)=.

** The cheaper half: a run-wide glyph path that is already built

=cooked--box-glyph-bits= and =cooked--box-glyph-image= already accept a =COUNT=
parameter and render a genuinely run-wide bitmap (=cooked-deco.el:256=, =:312=).
=cooked--apply-glyph-deco= calls =(cooked--deco-image deco size window)= with
three arguments — i.e. =count= = 1 (=cooked-deco.el:1057=).

The docstring at =:888-893= asserts the run-wide path is what
=cooked--apply-glyph-deco= does, and refers to a test named
=cooked-adjacent-box-glyphs-share-only-a-run-wide-image=. Neither is true in the
tree; the test that exists is =...-do-not-share-a-display-property=
(=tests/cooked-tests-glyph.el:24=). *The docs are ahead of the code* —
consistent with the =wip optimization= / =Perf improvements= commits and the
dirty =src/lib.rs=. The rasterizer is done; the apply path was never switched
over. Fix the two stale docstrings either way.

** Caching and IPC: cooked wins outright

The two sides made opposite bets. cooked *caches everything and re-emits
nothing*. ghostel *caches nothing on the image path and re-emits everything*.

Copies for one distinct image, wire to screen:

|                               | cooked                                                | ghostel                               |
|-------------------------------+-------------------------------------------------------+---------------------------------------|
| decode/inflate                | 1 (in place)                                          | in libghostty                         |
| encode to PPM/PNG             | 1 (raw only; PNG passed through)                      | *per placement, per redraw*           |
| boundary copy                 | *1, ever* (=make_unibyte_string=)                     | *per placement, per redraw*           |
| =create-image=                | once per distinct =(id cols rows cell-w cell-h)=      | *per placement, per redraw*           |
| steady state, image on screen | *zero bytes cross*; 12-byte placement record per cell | full re-convert + re-copy + spec hash |

A 1920×1080 placement costs ghostel ~6 MB of allocation, ~6 MB of memcpy, and a
spec hash over ~6 MB *every redraw that dirties any row*. Emacs' =image-cache=
saves the decode on a spec hit; it does not save the conversion, the copy, or
the hash.

Two cooked mechanisms with no ghostel counterpart, both worth keeping in mind
when the coalescing work touches this code:

- =cooked--image-specs= is *weak on the value, with the buffer text as the
  strong reference* (=cooked-deco.el:668=), so "is this image still displayed?"
  is answered by the GC rather than a refcount protocol.
- =cooked--flush-image-specs= (=:711=) reaches *into Emacs' own image cache* on
  eviction — otherwise a 34-frame gif at 3 MB/frame leaves thousands of decoded
  rasters resident for the full =image-cache-eviction-delay= while every ledger
  says the memory is gone.

Also cooked's: content-addressed image identity (a 128-bit digest, so a program
redrawing the same picture every frame costs one decode, and a client reusing
its own =i== for a different picture cannot make two images alias — ghostel keys
on client =image_id= and inherits both problems), and frame shedding
(=state.rs:260=, 61 MB → 8 MB at 8 frames/drain).

ghostel pays for re-emitting in correctness debt cooked does not have:
=ghostel--kitty-strip-orphan-top= (=ghostel-kitty.el:365=) exists to clean up
stacked zero-width overlays and orphan slices that scrollback eviction creates,
by /counting/ zero-width overlays per position. Those are repairs for damage the
architecture causes.

** Protocol coverage, briefly

ghostel inherits much broader /parse/ coverage from libghostty-vt (all four
transmission mediums, image numbers, placement ids, the full delete taxonomy;
animation is parsed and refused at its pinned rev, and is implemented upstream).
What it /uses/ is narrower: only =.virtual= and =.pin= placement locations, =z=
ignored, source rects refused with an Emacs error that never reaches the client,
and multiple simultaneous virtual placements collapse into one image.

cooked has three protocols where ghostel has one — kitty + sixel + iTerm2
=OSC 1337= — and declines what it does not support *out loud*, with the
protocol's own error response, honouring =q=1/q=2=. A client told no falls
back; a client ignored waits.

*Sixel: confirmed absent from ghostel and absent from libghostty-vt entirely* —
the only occurrence in the vendored tree is the DA1 enum value =sixel = 4=.
=src/emu/sixel.rs= is a full two-pass decoder verified pixel-for-pixel against
=sixel2png=. Nothing to borrow in either direction.

** Font metrics: the one place ghostel solves something cooked does not

Correction to an early assumption: =GlyphMetricsCache.zig= is *not* a
box-drawing rasterizer. ghostel has no custom glyph rasterization at all. The
cache holds *Emacs font metrics*, keyed =(page_serial, style_id, utf8 bytes)= →
packed ={width, ascent, descent, pixel_size}=, and it exists to make
fallback-font glyphs fit the monospace grid.

=adjustGlyph= (=Renderer.zig:662=) measures a cluster via
=composition-get-gstring= / =font-at=, computes three independent scale ratios
(width, ascent, descent), takes the min, floors it against the font's pixel size
to stop Emacs rounding up, and emits:

#+begin_src elisp
(display ((min-width (N)) (height SCALE)))
#+end_src

=adjustWidth= (=:719=) additionally lets a standalone icon claim the following
cell when its aspect ratio exceeds the cell's — but only when both neighbours
are blank, hiding the following space with =(space :width 0)=.
=ghostel-glyph-scale-floor= lets the user opt out toward natural-size CJK at the
cost of grid alignment.

cooked has nothing here: no =min-width=, no =font-at=, no =space= specs anywhere
in =lisp/=. cooked's width model is grid-side only — =unicode_width= per cell
with =CONTINUATION= for the second half of a wide char. The grapheme story in
=src/emu/text.rs= is *better* than ghostel's (a streaming =Segmenter=
implementing kitty's text-sizing algorithm, correct across =read(2)= boundaries,
with its one disagreement with =unicode-width= stated outright, versus
libghostty's coarser =hasGrapheme=) — but if the /font/ renders that cluster 1.4
cells wide, cooked's grid is right and the screen is still misaligned.

That asymmetry is what makes this cheap to add: cooked already knows cluster
boundaries and declared widths. What is missing is asking Emacs what the font
actually did. ghostel's 20 tests in =test/ghostel-glyph-test.el= are a
ready-made spec.

Two caveats on their cache, if it gets ported: =page_serial= in the key means
entries are per-page-node, so rows churning through scrollback accumulate dead
entries that nothing prunes until a font change — a slow, session-length leak.
And the key hashes cluster bytes with =autoHashStrat(.Deep)=, so a lookup is a
Wyhash over the cluster, not a pointer compare.

*** The framing that matters: repair vs destroy

The two projects solve *different halves* of the cell disagreement, and ghostel's
half is the one users see.

- *ghostel prevents it*: measures the suspect glyph and *shrinks it* to fit.
  The character stays legible, the row stays aligned.
- *cooked detects it and destroys the overflow*: =cooked--guard-row-width=
  (=cooked.el:1907=) asks =vertical-motion= whether the row soft-wrapped and, if
  so, *deletes characters off the end* until it doesn't, then draws a truncation
  arrow in the fringe.

cooked's machinery is far more sophisticated at *knowing* it has a problem — a
per-font ligature-vs-proportional probe, a stamped invalidation model, a
three-tier fast path with a microbenchmark behind each tier. ghostel's is far
better at *fixing* it.

*So: adopt the scaling as a step 2.5 inside =cooked--guard-row-width=.* When a
row is found to wrap, walk its clusters, measure the offenders, and put
=(display ((min-width (N)) (height SCALE)))= on them — keeping the trim as the
last-resort backstop it deserves to be. Two parts are load-bearing: the
*three-way min* of width/ascent/descent ratios (a row realizes
=max(ascent) + max(descent)= across the glyphs sharing its baseline, so scaling
by the sum ratio can leave one side over the line), and the
=@floor(pixel_size × scale) / pixel_size= *quantization*, without which Emacs
rounds the scaled height back up and the cell overflows anyway.

cooked already has both hard prerequisites ghostel had to build: a per-cluster
width the core computed (=Run::cols=, =cell.rs:374=) and a correct segmenter
(=text.rs=). What it needs is a metrics cache, or it will re-=font-at= per cell
per drain — the same trap it already fell into with =vertical-motion= at 445 µs
per border row. Use *ghostel's key/value shape with cooked's invalidation*:
=cooked--wrap-cache= is already stamped on exactly the right things (font,
=face-remapping-alist=, geometry) and already thrown away wholesale when the
stamp moves, where ghostel flushes only on default-font change and never prunes
=page_serial=-stale entries.

*** Two measurements from cooked's side worth keeping visible

The *ligature finding* (=cooked.el:1763-1780=) overturned a blanket assumption:
across four monospace fonts × 27 ligature sequences × composition on and off,
*0 of 27* rendered at anything other than nominal =frame-char-width × length=. A
monospace font draws a ligature inside the cells its characters already
occupied — that is what makes it monospace. The control, a quasi-proportional
face, got 26 of 27 wrong. *Ligatures are not the hazard; proportional faces are*,
and ghostel has no equivalent investigation — its =probeCoverage= starts at
U+00FF, so ASCII is never measured and a =buffer-face-mode= produces silent
drift it cannot see.

The *guard tiering* is measured, not assumed. Before the tiers existed the guard
ran fully for every row of every drain on a graphical frame: on a 248-column
frame, 2.2 ms per 45-row drain for ASCII, 5.1 ms for CJK, and *24.5 ms for box
drawing* — more than a whole 60 Hz frame, on the apply path, to conclude there
was nothing to do. Of that, =vertical-motion= over a border row was 445 µs of
545 µs.

*** Smaller items on this axis

- *=ghostel--around-font-scale=* (=ghostel.el:4779-4809=) — advice on
  =text-scale-mode=, =buffer-face-mode= and =global-text-scale-adjust=,
  snapshotting which windows were anchored and re-anchoring after. cooked hooks
  =text-scale-mode-hook= only, so it misses =buffer-face-set= /
  =variable-pitch-mode= entirely — which is precisely the case
  =cooked--ascii-fixed-pitch-p= exists to detect, so cooked currently detects it
  without ever being told to re-measure.
- *=ghostel-glyph-scale-floor= plus =ghostel-debug-describe-glyph-scaling=* —
  turns the alignment-vs-legibility trade into a user choice and lets someone
  with a misaligned row find out why. cooked has *no user-facing story here at
  all*: a row silently loses its last character and gets a fringe arrow, and
  nothing tells the user their face isn't fixed-pitch even though
  =cooked--ascii-fixed-pitch-p= already knows.
- *The minibuffer resize exception* (=ghostel.el:4763-4770=) — suppress
  rows-only resizes while a minibuffer is active, because fish clears and
  re-emits its prompt on every SIGWINCH, so an =M-x= cycle produces two
  repaints. Skipped on the alt screen. A real cooked-visible flicker.
- *=ghostel-cell-pixel-scale=* (=:4693=) — the cell size *reported to the child*
  scaled by DPI/96, so image tools sizing from XTWINOPS 16t match standalone
  Ghostty's physical-pixel output. cooked reports logical pixels and would draw
  at half size on HiDPI. ~15 lines, and =docs/IMAGES.md= already cares about
  this class of problem.

Worth keeping on cooked's side: *no =selected-window= fallback, argued rather
than assumed* (=cooked.el:2366=) — measuring a row against a window showing
someone else's buffer at someone else's width "is not a weaker measurement, it
is a meaningless one", and the guard *acts on the answer by deleting text*. Plus
the refusal to report a cell size for a buffer displayed nowhere, because "a
guessed cell size would reach the child as fact and outlive the guess". And
*XTWINOPS discipline*: silence where the protocol cannot say "unreported", an
explicit failure status where it can, and 21t refused because it would put the
title on the child's *input* stream.

* 3. Process model and module distribution
:PROPERTIES:
:AXIS: pty ownership, threading, packaging, buffer lifecycle

** Architecture diff

|                     | cooked                                                                                    | ghostel                                                                                                                              |
|---------------------+-------------------------------------------------------------------------------------------+--------------------------------------------------------------------------------------------------------------------------------------|
| PTY owner           | Rust, always. One path.                                                                   | Zig by default *or* Emacs =make-process= + TRAMP handlers. Two paths, one API.                                                       |
| Emacs↔core channel | wake *pipe carrying one byte*; Lisp drains via =cooked--drain=                            | event pipe carrying *serialized Lisp sexp text*, =eval='d by =ghostel--events-filter=                                                |
| Backpressure        | real: reader stops =read(2)=ing at =backlog_limit=, pty fills, child blocks in =write=    | buffered event writer; no pty-level backpressure                                                                                     |
| Wakeup pacing       | =Notifier= with =min_interval= floor, in-flight token, quiescence hold, resample deadline | 33 ms coalescing redraw timer, immediate bypass for keystroke echo                                                                   |
| Threading           | one reader thread; plain =Mutex=, poisoning recovered by policy                           | reader thread + detached reaper; =RecursiveMutex= because libghostty handler callbacks re-enter the terminal from inside =nextSlice= |
| Reaping             | =reaped=-flag mutex serializes =killpg= against =waitpid=                                 | Lisp sentinel =signal-process … 9= unconditionally; no flag guarding the race                                                       |
| Signals             | =killpg= to the group, job-control chars read from *termios* (so =stty intr ^X= works)    | =signal-process=; no termios-derived job control                                                                                     |
| Resize              | =pending_resize= retried until the tty *reads back* the requested size                    | one ioctl, =EIO/ENXIO= swallowed                                                                                                     |
| Windows             | none                                                                                      | =ConPtyProcess.zig=, 810 ln                                                                                                          |

** What cooked does better here, and why it matters

- *The wake protocol is a token, not a message.* One byte, not re-armed until
  Emacs acknowledges by draining (=session.rs:798-813=). ghostel serializes Lisp
  /source text/ into a pipe and =eval=s it on the Emacs side
  (=NativeProcess.zig:176-232=) — larger attack surface (child-controlled OSC
  payloads become substrings of text that gets =eval='d, with a
  three-character escaper between), more allocation, and no natural place to put
  backpressure. "Carry the fact that something changed, let Emacs ask what" is
  what makes =Notifier='s throttle/hold/quiescence logic expressible at all.
- *Backpressure is real.* Under a multi-hundred-megabyte flood ghostel's
  advantage is that Emacs stays responsive; cooked's is that memory stays
  bounded and the child is told to slow down. cooked's is the stronger property.
- *Resize confirmed by read-back*, because a child's own init can overwrite a
  successful =TIOCSWINSZ= and the difference is otherwise invisible.
- *One PTY path, and it is the strong one.* No =ghostel-use-native-pty=, no
  second write path, no =backend_handoff_mutex= protecting a backend one path
  can retire while another blocks writing to it.

On the published "Native vs Emacs PTY" numbers (=cat= 10 MB, median of five, M4
Max: ghostel native ~110 ms, Emacs-PTY ~220 ms, vterm ~550 ms, eat ~1.8 s):
cooked is on the winning side *by construction* and pays none of the
two-backend cost. What ghostel buys with the second backend is exactly one
thing — TRAMP, where Emacs owns the spawn so =file-name-handler-alist= applies.
So the honest scoring is that ghostel's second backend is not redundancy, it is
the remote feature cooked lacks. See §6: ROADMAP §7 (detach/reattach, a daemon
holding the pty local to the remote host) is a /better/ answer than streaming
bytes through TRAMP into a main-thread filter, and building both would be
building ghostel's two-backend problem.

** The desktop refusal holds — and ghostel is the evidence

=docs/DESIGN.md:1293= declines =desktop= registration. ghostel registers, and
then needs a four-branch skip list (remote, command-identity, missing directory,
dead shell) *plus* =ghostel-desktop--shield-replay=: a =run-at-time 0= that
undoes the point/mark/read-only that =desktop-create-buffer= replays onto the
restored terminal, because a saved active mark flips semi-char mode into copy
mode. That timer is the tell — registering with desktop means fighting desktop's
own restore semantics from a deferred callback. It also writes exec'd argv to the
desktop file in plaintext (and says so in the docstring). cooked's bookmark
records the command line but never re-runs it, which answers the same hazard
better.

** Prebuilt module download, and the checksum they do not have

=lisp/ghostel-module-install.el= (620 ln). Mechanism worth porting:

- *Platform detection* (=:75=): =(car (split-string system-configuration "-"))=
  for arch, normalizing =amd64=→=x86_64=, =arm64=→=aarch64=; OS from
  =system-type= plus an explicit Termux/Android check, because bionic modules
  are not glibc-interchangeable.
- *Version pinning*: requests =/releases/download/v<min>/<asset>= by default,
  *not* =latest=; =latest= is opt-in by prefix arg, and the fetched version is
  recovered by parsing the redirect target out of =url-current-object=.
- *Version sidecar*: a one-line =ghostel-module.version= file, written by the
  build and by the downloader. The loader reads it *before =module-load=* and
  refuses to map a stale =.so= (=:566=), so a fresh install loads into the same
  Emacs without a restart. Every failure path is ordered to end in "sidecar
  absent" rather than "sidecar stale".
- *Atomic install* (=:262=): write a sibling temp file and =rename-file= it into
  place — renaming swaps the directory entry to a new inode, so a running Emacs
  with the old file mmap'd keeps a valid mapping. Writing to =dest= directly
  truncates the live inode → SIGBUS. cooked's Makefile already knows this rule.
- *Never prompt at load or byte-compile time* (=:521-540=) — only at an
  interactive entry point. =ghostel-module-directory= lets the module live
  outside the package tree so a package-manager reinstall cannot delete a
  mapped =.so=.

*Finding: there is no checksum and no signature anywhere.* A grep for
=sha256|checksum|secure-hash|gpg|signature= across =lisp/ Makefile .github/=
returns nothing relevant. The entire integrity story is
=(unless (string-prefix-p "https://" url) (error …))= plus trusting GitHub's TLS
and =url-retrieve-synchronously='s certificate checking. The Windows path
additionally side-loads =conpty.dll= and =OpenConsole.exe= and
*warns-but-continues* on failure.

If cooked ports this, publish =SHA256SUMS= alongside the release assets and
verify with =(secure-hash 'sha256 …)= against digests *compiled into the =.el=*,
pinned where =cooked--minimum-core-version= would live — so the trust root is
the package MELPA gave you, not the CDN you are about to fetch from. ~30 lines,
and it is the difference between "trusts GitHub TLS" and "trusts the tarball",
which is the posture a native module that gets =dlopen='d into your editor
deserves.

Related: =cooked--check-core-drift= (=cooked-module.el:264=) is the same hazard
from the other side — Lisp calling a defun the loaded core lacks. The sidecar
generalizes it to "before we even map it".

*** The artifact has to carry terminfo, and that changes the staleness model

Today the compiled database comes from the checkout — =terminfo/db/c/= and
=terminfo/db/63/=, both spellings written because "the =tic= that wrote ours
cannot know which the reader will want" (commit 83206c1). *A prebuilt install
has no checkout.* A download that ships only the =.so= leaves the child with no
terminal description, =TERM= falls back, and every capability =terminfo/cooked.ti=
exists to state — and that DECRQM answers 4 for, to make the claim auditable —
is silently lost. So the release artifact must carry the db, the way ghostel's
does.

Three consequences, the first of which is not obvious until the checkout is gone:

1. *Staleness has to change from mtime-vs-source to version-vs-sidecar.*
   83206c1 restored the ordinary staleness check — "an entry older than
   =terminfo/cooked.ti= is not used but rebuilt, into =user-emacs-directory=" —
   and a downloaded install has no =cooked.ti= to compare against. So the version
   sidecar (§above) must carry a *terminfo* version beside the module ABI
   version, and =cooked--terminfo-database= must compare that rather than an
   mtime. This also restores the property the encoded form could not have:
   regenerating needs =tic=, whose absence is the reason to ship compiled at all.
2. *Both subdirectory spellings must survive the tarball*, for the same reason
   they are both written now. ghostel's remote push writes four
   (=x/=, =g/=, =78/=, =67/=) because it has two entry names × two layouts;
   cooked has two names and needs the same coverage.
3. *The db is inside the same trust boundary as the =.so=* — it is data the
   child's ncurses parses — so it belongs under the same =SHA256SUMS= as the
   module. "An entry a library cannot parse is skipped rather than fatal" is the
   safety floor that makes shipping compiled terminfo sound at all, and it still
   holds for a downloaded entry; it is not a substitute for integrity.

*** =TERMINFO=b64:…= comes back, scoped to the one case a directory cannot reach

Commit 83206c1 removed the encoded form with a good argument, and that argument
is untouched: for a *local* child a directory needs no probe, no ncurses-6
branch and no reasoning about which library macOS links, so paying for =b64:=
there buys nothing. What it did not say is that =b64:= is never right — only
that it should not be the default.

*Its real customer is the remote spawn.* =TERMINFO=b64:<entry>= placed in the
child's environment needs *zero filesystem writes on the far end*. That deletes
the whole of ghostel's remote-terminfo apparatus — =ghostel--push-remote-terminfo=
(=ghostel-shell.el:375=) writing four layouts into a remote temp dir, plus the
=kill-buffer-hook= cleanup that has to bind =non-essential t= so deleting those
files cannot open a fresh TRAMP connection and prompt for a password when the
session is already gone. And the probe 83206c1 objected to is free here, because
a remote spawn is already running a command on the other side; or skip it
entirely and let an unresolvable =TERM= fall back to =xterm-256color= with a
message, which is what ghostel's ssh wrapper does regardless
(=etc/shell/ghostel.bash:256-365=).

So the policy is *a directory always, =b64:= only where no directory is
reachable*, which is precisely the remote case and nothing else. The read-only
local filesystem (Nix store, immutable container) looks like a second case and is
not a strong one: =temporary-file-directory= is effectively always writable, so
the directory path has a fallback that asks nothing of the child's ncurses
version. Leave that one alone.

Note what this buys cooked over ghostel on the same axis: ghostel's remote path
needs a writable remote temp dir, a multi-file write over the connection, and a
cleanup that can itself reconnect. cooked's would need one environment variable
— on a remote host whose ncurses is version 6, which is every remote host worth
the phrase in 2026, with the =xterm-256color= fallback covering the rest.

** Decline: ConPTY

=ConPtyProcess.zig= is real and reasonably complete (overlapped I/O, interrupt
events, =PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE=). But cooked's entire
differentiating bet — =Mode::{Cooked,Raw,Secret}= sampled from the master's
termios, =killpg= with tty-derived job-control characters — has no ConPTY
analogue. *There is no termios on a pseudoconsole*, so the input-ownership model
that makes cooked /cooked/ cannot be implemented there. Porting would mean
shipping a build where the flagship feature silently does not exist. Say so in
the README if anyone asks.

** =cooked-process.el= is the harder version of ghostel-compile, and it wins

ghostel runs =compile= in a real terminal buffer and then, on exit, one-way-doors
into =ghostel-compile-view-mode= — so *during* the build the buffer is not a
compilation buffer, =next-error= does not work, and recompile discards it.
cooked keeps the buffer a =compilation-mode= buffer throughout and feeds
=compilation-filter= unmodified strings at =process-mark=. Three things there
have no ghostel counterpart:

- *Wrapped-line rejoining as a debt incurred and repaid*: giving the child a
  width is what makes it wrap, so the rejoin is mandatory (=cooked-process--rejoin=
  is a =defconst=, not an option). The docstring carries the measurement —
  120 cols: 2.4 MB / 1.3 s; 8192 cols: 164 MB / 70 s, byte-identical output.
- *The progress bar as an overlay =after-string=*, replaced per drain and taken
  down at exit, so =compilation-mode= never parses it, =next-error= can never
  land in it, and =process-mark= never moves for it.
- *The fake process with rebound accessors*: =cl-letf= on
  =process-status/process-exit-status= for exactly one call, so
  =compilation-sentinel= sees a real exit — and the sentinel is detached
  /before/ calling it, because =compilation-sentinel= deletes the process, which
  re-runs the sentinel, which would annotate the buffer twice under the still-
  active rebinding. A bug found and written down.

=grep-mode= is excluded on principle, not as a special case: a consumer that
/parses/ the styling must keep the pipe, because resolving SGR away would leave
a grep buffer correct and unhighlighted.

** Explicit modes vs derived policy

ghostel has five user-chosen modes (=semi-char= default, =char=, =emacs=,
=copy=, =line=). cooked derives one of =cooked/prompt/command/raw/alt=
from termios + OSC 133 + alt-screen (=cooked.el:585-660=).

*What explicit modes get right:*

1. A read-only stable view *on demand, with no signal required* — =copy= mode
   works for a shell with no OSC 133, over ssh, in a non-instrumented REPL.
   cooked's answer there is =peek=, which is close but arrives only by a
   keystroke the user must know.
2. *Selection survival is a first-class decision, not a by-product.* ghostel
   switches mode when the mark activates or point leaves the cursor, so
   =C-SPC=, expand-region, =consult-line=, isearch and avy all stop output
   clobbering the selection, with =ghostel-maybe-leave-input= as a hook /and/
   =:after= advice for packages that have none. *cooked freezes only in evil
   visual state; a non-evil user selecting with =C-SPC= gets no protection.*
3. =char= mode exists for programs that want =C-c/C-x/M-x= themselves
   (=emacs -nw= inside the terminal). cooked's =alt= map still reserves =C-c=
   unconditionally; there is no "give it literally everything" state except one
   key at a time via =C-c C-q=.
4. User-legible state: =:Char/:Copy/:Line= says what /you/ chose. A wrong
   inference is harder to argue with than a wrong choice.
5. Line mode works *with no shell integration at all* (VT cursor as the input
   boundary, =ghostel-prompt-regexp= fallback) — =python3=, =irb=, =sqlite3=.
   cooked's Emacs-owned line needs an OSC 133 =B= *plus* an ownership license.

*What derived policy gets right:*

1. The common case needs no mode at all. ghostel needs =C-c C-l= to edit locally
   and =C-c C-t= to read.
2. *It cannot be wrong about a full-screen program.* ghostel's line mode collides
   with alt-screen TUIs and has to detect and drop out, then arm an auto-resume
   (=ghostel-line-mode.el:613-643=), plus a 4-way decision for =C-c C-l= pressed
   on the alt screen. cooked's =alt= wins by construction; that failure mode
   does not exist.
3. *Line mode's snapshot/restore is a workaround cooked does not need.* ghostel
   captures in-progress input, deletes it, lets the renderer rewrite the buffer,
   re-inserts at the new prompt-end (=:295-380=), disarming =buffer-undo-list=
   around the round-trip — because the renderer owns the buffer. cooked's input
   region is genuinely Emacs' text with a process mark.
4. ESC needs no routing policy.
5. IME works for free at a prompt.

On history/completion the two arrive at the same place from opposite ends:
ghostel's line mode reimplements completion in Emacs and carries its own
200-entry history ring; cooked's =cooked-delegate-key= hands the line /back/ to
ZLE for one keypress (=docs/DESIGN.md=, "Delegation is one primitive"). cooked's
design is cleaner; ghostel's works on more shells today.

** evil: they are solving different problems

The 1025-vs-568 line gap is mostly *machinery cooked does not need*.
=evil-ghostel= drives the /shell's line editor over the PTY/ from evil's
operators; =cooked-evil= drives /cooked's keymap policy/ from evil's state and
lets the operators act on real buffer text.

The clearest illustration: =evil-ghostel= needs an entire *ESC routing
subsystem* — =auto/terminal/evil=, a buffer-local override, =C-c C-r= with
numeric prefixes 1/2/3, a one-time echo hint, and a one-shot =C-c <escape>=
(=:855-930=) — because it cannot tell who owns the keyboard. cooked reads
termios + OSC 133, puts evil in emacs state for the child, and ESC forwards.
*Absent by design* is the correct entry in that row.

What =evil-ghostel= handles that =cooked-evil= does not, exhaustively: ESC
routing policy · per-key insert-state Ctrl passthrough (18 generated closures)
with local-map fallback · =<delete>= passthrough · PTY-driven
=d/c/s/r/x/X/D/C/S= with input-region clamping (backspaces N times, then
bracketed-pastes the replacement) · block-wise operator application via
=evil-apply-on-block= · *autosuggestion boundary detection* (reads the cell's
=:foreground=, tests dim + low saturation, requires a uniform run to EOL, so
=$/A/p= never right-arrow into a zsh-autosuggestion the shell would accept,
=:296-358=) · cursor driving by arrow keys with an =accept-process-output=
settle loop up to 10×50 ms · all four of =a/A/i/I= with off-row snap-back · =$=
stopping before right-prompt/padding · =j= clamped to the cursor row · =G= → live
cursor · =u= → readline =C-_= (redo unsupported) · count/register-aware
bracketed paste with suggestion guard · redraw-time visual-marker restoration ·
cursor-shape ownership + blink stop · an =evil-escape= advice suppressing the
speculative first-key preview that the foreign-edit interceptor would leak to
the PTY · a vim-=iskeyword= syntax table · opting out of ghostel's own
mark→copy-mode switch.

Every one of those is a consequence of the shell always owning the line.

What =cooked-evil= has that =evil-ghostel= does not: state-driven keyboard
ownership (the whole ESC subsystem replaced by one signal) · per-state render
policy (=still= for normal/motion/operator, =frozen= for visual) · =C-z=
return-state repair · *OSC 133 command text objects* (=vic/vac=,
count-extending, with the empty-inner-range subtlety handled) · a visual-case
read-only guard that *returns rather than signals*, because a signal skips
=post-command-hook= and leaves evil believing in an invisible visual state so
the next =v= /exits/ visual · =cooked-evil-undo= reporting "No further undo
information" instead of leaking "Buffer is read-only" · corfu/
=completion-in-region= yield on RET · =evil-collection= precedence handled
correctly.

That refusal discipline — return-or-message rather than signal, with the reason
written down — is not present on the ghostel side.

** IME

ghostel's =lisp/ghostel-ime.el= (185 ln) wraps buffer-local
=input-method-function=: binds both =inhibit-read-only= *and*
=buffer-read-only= (hangul2 checks the variable directly), measures point before
and after, deletes the transient insert, forwards the commit as UTF-8, and while
composing stands down insert forwarding and redraw via two hooks. It re-asserts

cooked has zero IME code and mostly does not need it: at policy =cooked= (every

(=cooked--with-child-edit/inhibit-read-only= for the delete) but would need a
redraw-inhibit predicate analogous to =ghostel-inhibit-redraw-functions=. The
=buffer-read-only=-not-just-=inhibit-read-only= detail and the
=post-command-hook= re-assert are both hard-won; copy them verbatim.

** Mouse

cooked is ahead on routing correctness: dispatch into the buffer *under the

** Word boundaries and copy

ghostel: =ghostel-word-boundary-string= (default
=" \t\"'`|:;,()[]{}<>$│"=) realized into =ghostel-mode-syntax-table= *in place*
(=ghostel.el:758=) so live buffers pick up a customize. =.= and =/= are word
constituents, so double-click and =M-f= take =api.example.com= and
=~/src/foo/bar.txt= whole; U+2502 is a boundary so TUI panes do not merge. Tests

actual double-click chain) because those classify differently. Copy is filtered

same problem structurally instead: =cooked-rejoin-wrapped-lines= makes a wrapped
row part of the same buffer line, so there is no soft-wrap newline to strip, and
trailing padding is never emitted. That is the better foundation, but it leaves
two real gaps: *double-click over a path or URL splits at =/= and =.=*, and a
copy out of a box-drawn TUI pane can still take the borders.

Take the syntax table (~40 ln, and steal the two-chain test discipline).

** TRAMP is much cheaper than the ROADMAP bills it

=docs/ROADMAP.md= §5 says "detecting 'we are remote' reliably is the crux". It
is not. =cooked--host= already carries it and =cooked--foreign-host-p=
(=lisp/cooked.el:310=) already decides it correctly. What is missing is only the
*consequence*: cooked treats a foreign host as a reason to *stop*
(=cooked-osc.el:560=, deliberately); ghostel treats it as a reason to *rewrite*.

=ghostel--update-directory= (=ghostel.el:3534=, remote branch =:3594-3614=):

#+begin_src elisp
;; Remote host - construct a TRAMP path.
(let ((prefix (file-remote-p default-directory)))
  (setq path (if prefix (concat prefix filename)
               (format "/%s:%s:%s"
                       (or ghostel-tramp-default-method tramp-default-method)
                       host filename))))
...
(if (file-remote-p path)
    ;; Trust the shell's report; skip file-directory-p to avoid
    ;; synchronous TRAMP connections on every cd.
    (setq default-directory (file-name-as-directory path) ...)
#+end_src

Two details to take verbatim: *reuse the existing remote prefix* so
method/user/multi-hop survive, and *skip =file-directory-p= on the remote
branch* — validating opens a TRAMP connection on every =cd=. Their
=ghostel--local-host-p= (=:3517=) also strips a trailing =.local= for macOS
kernel-hostname drift, a case =cooked--foreign-host-p= does not handle.

*Sketch:*

#+begin_src elisp
(defcustom cooked-remote-directory 'tramp   ; 'tramp | nil
  "What to do with an OSC 7 report from another host.")
(defcustom cooked-tramp-default-method nil ...)

;; in cooked--set-directory, replacing the bare `unless (cooked--foreign-host-p)':
(let ((path (url-unhex-string (match-string 2 url))))
  (if (cooked--foreign-host-p)
      (when (eq cooked-remote-directory 'tramp)
        (setq default-directory
              (file-name-as-directory
               (concat (or (file-remote-p default-directory)
                           (format "/%s:%s:" (or cooked-tramp-default-method
                                                 tramp-default-method)
                                   cooked--host))
                       path))))      ; NO file-directory-p here
    (when-let* ((name (cooked--local-name path)) ...)
      ...)))
#+end_src

Three follow-ons, all predicted by cooked's own docs:

- =cooked--local-name= (=cooked-util.el:367=) refuses a remote name from the
  byte stream — the hostile-=cat= defence at =cooked-osc.el:548-553=. *Keep it
  for the local branch.* The remote branch must construct the TRAMP name from
  =cooked--host=, never accept one from the payload. The defence is preserved
  exactly: a hostile stream can still only name a host it is already claiming
  to be.
- =cooked-file-link.el= must *stop* resolving file:line refs when
  =default-directory= is remote, or every settled scrollback batch becomes
  remote =file-exists-p= round-trips. ghostel does exactly this
  (=ghostel-links.el:539-541=). Steal the guard; do not steal the idea that
  links become remote links.
- =cooked--native-completion= (=cooked-completion.el:76=) should decline on a
  foreign host — =DESIGN.md= already flags this and the change makes it visible.

*Portability: ~95% TRAMP-generic.* Pure Elisp, no ghostty dependency.

*Ship the mapping alone first.* The full remote-spawn story is architectural:
ghostel force-disables its native PTY for remote (=ghostel.el:4104=) and
respawns through =make-process :file-handler t= (=:4141=), which is a second
spawn path cooked does not want. The mapping alone already delivers ROADMAP §5's
described scenario — =find_file config.rs= from an ordinary outbound =ssh=
opening a real local buffer with your LSP and keybindings.

** Shell history for free

=ghostel-shell-history-commands= (=ghostel-shell.el:128-151=) is four lines of

free once the mapping above lands:

#+begin_src elisp
'((bash . "bash -ic 'history -r; fc -lnr 1'")

/interactive/ history search with the user's own bindkeys — but for "pick a past

a subprocess reading the histfile the shell already wrote. Strictly weaker than

competes. Insert via cooked's existing input path, so no one-way door. Makes
=consult-cooked-history= (ROADMAP:205) a ~30-line extension.

** Deferred detection — the third suspected scroll cause, already answered

*Correction to an earlier draft of this section, which said cooked paints
goto-addr overlays from inside the drain, per damaged row, every frame.* It does
not, and has not on =main= since the initial commit: =cooked--fontify-region= is
registered with =jit-lock-register= by =cooked--sync-fontification=, so the scan

this section did not, and the =cooked-link.el:349= cite was the *definition* of

of the code, just not =main='s: branch =links= (464daf7) scanned per rendered
row from the drain and once per batch from the scrollback append.

cooked's deferral is the *stronger* of the two, because ghostel scans every
repainted row including ones a flood pushed past the viewport, where cooked
scans only what someone looks at. So the apparatus below is not a thing to port;
it is the shape cooked would have needed had it not had jit-lock. ghostel's pass
is *deferred, coalesced, chunked, and newest-end-first*:

- the renderer publishes the repainted region;
- =ghostel--queue-plain-link-detection= (=links.el:822=) merges it into

- the drain takes =ghostel--link-detection-chunk= = 100 000 chars from the
  *newest end first* and re-arms (=:785=);
- =ghostel--flush-plain-link-detection= (=:810=) finishes the job for a dead
  terminal.

What *is* worth taking from ghostel here is the soft-wrap joining, below, and
the two cheap filters: skipping the cursor's row and the prompt, and using text
properties rather than overlays. The debounce is already had for free, and
=cooked-detect-links-on-alt-screen= was already not a necessary defence —
=cooked--sync-fontification= answers the alternate screen one level up.

** Secrets: cooked wins, with one bug

*Bug-shaped:* cooked =clear-string=s whatever =cooked-password-function= returns.
ghostel deliberately does *not* clear the source-supplied secret
(=ghostel.el:3222-3232=) because an auth-source backend may hand out a string
shared with its cache — zeroing it corrupts the cache in place. ghostel clears
only the freshly-allocated =(concat pwd "\r")= wire copy, in a nested
=unwind-protect= so it happens even if the PTY write throws. Either adopt that
split, or document that sources must =copy-sequence=.

*Gap:* cooked's detector is termios-only, so an =ssh= password prompt from a
/remote/ program the local PTY cannot see is missed. ghostel adds a cursor-row
regex fallback (=ghostel-password-prompt-regex=, = =comint-password-prompt-regexp=)
*gated on the shell being remote* (=ghostel.el:3057=) — and gating it on
remote-only is exactly what keeps vim and less from false-positiving. cooked
already has =cooked--foreign-host-p= for the gate.

*Worth taking:* =ghostel-password-prompt-functions= is a *hook chain* run with
=run-hook-with-args-until-success= (auth-source, then pass, then =read-passwd=
at the tail), where =cooked-password-function= is a single slot. The chain
composes and matches cooked's own seam idiom elsewhere. Their docstring ships a
TRAMP-aware =auth-source-pick-first-password= example and warns that returning
=""= counts as a hit.

*What cooked does better — and the agent called this the single most important
correctness property in the area:* secret handling under divided attention. If
=cooked--attention= is =away=, the read is *held* and only a message shown,
because =read-passwd= takes the selected frame's minibuffer — otherwise the next
keys the user types in an unrelated buffer go to this child, followed by a
newline. =cooked--resume-secret= raises it when attention returns, with three
guards. ghostel's minibuffer opens wherever the user happens to be.

The *epoch counter* is likewise stronger than ghostel's cursor-row suppression: a
stale answer is refused ("Nothing is asking for that any more; not sent") and a
stale quit does *not* send =C-c= to whatever is running now. And =README.md='s
"On passwords" states the heap/GC/auth-source limit plainly instead of claiming
the secret leaves no trace.

** When to redraw

*cooked — core-driven, no timer anywhere.* The decision lives in Rust, in
=Notifier::flush= (=src/session.rs:424=), which writes one byte to a wake pipe.
Four gates, consulted in order, and every one can only /delay/:

| Gate                                                                    | Holds while                       | Retired by                                          |
|-------------------------------------------------------------------------+-----------------------------------+-----------------------------------------------------|
| #ERROR                                                                  | a wake byte is already in flight  | =Session::ready= (=:826=) — Emacs finished drawing |
| =sync_until= (=:281=)                                                   | child is mid-frame under DEC 2026 | child's =2026 l=, or =SYNC_TIMEOUT= 150 ms          |
| =min_interval= (=:245=)                                                 | < 8 ms since last wake            | the clock                                           |
| =hold(quiescence)= (=:168=, =QUIESCENCE= 500 µs; =HOLD_CEILING= 150 ms) | child wrote anything < 0.5 ms ago | pty going quiet, or the ceilings                    |
#+TBLFM: $1=notified= (=session.rs:218=)

The Lisp side is a pure consumer. =poll_wait= (=:537=) shortens the reader's
poll to the throttle's remaining window so a deferred notification doesn't wait
out =POLL_TIMEOUT_MS=. DESIGN.md's measured claim: 40 applies against 91
redisplays under a =yes= flood, 155 against 215 for a spinner — *renders never
outrun redisplays*, so Emacs is the pacer and 8 ms is only a floor.

*ghostel — Elisp timer, adaptive, plus an immediate-echo bypass.*
=ghostel--invalidate= (=ghostel.el:4283=) is the whole scheduler:

- *No window showing the buffer → cancel the timer, set a pending flag.* Zero
  Emacs work for hidden terminals; =ghostel--pre-redisplay= (=:4888=) flushes on
  =pre-redisplay-functions= when it becomes visible.
- *Keystroke echo bypass*: within =ghostel-immediate-redraw-interval= (0.05 s)
  of a send → synchronous redraw. The one urgent path cooked deliberately lacks.
- Otherwise a coalescing =run-with-timer= at 0.033 s ≈ 30 fps, with
  =ghostel-adaptive-fps= dropping to 0.016 s for the first frame after >100 ms
  idle. One-shot, not rescheduled while idle.
- *Synchronized output is frame skipping in the module*: =Renderer.redraw=
  returns =false= while mode 2026 is set (=Renderer.zig:148=) — *with no
  timeout*, so a child that leaves 2026 open freezes the display until
  =ghostel-force-redraw=.
- Re-entrancy is a hard =error.ReentrantRedraw= where cooked folds and retries.

Net: cooked absorbs bursts by *holding the frame* and paces off Emacs' own
completion signal; ghostel absorbs bursts by *dropping frames* on a wall clock.
cooked additionally has =cooked-backlog-limit= backpressure that blocks the
child in =write()=; ghostel's reader never blocks the child.

** Marker preservation: ghostel has a floor cooked lacks

=saved_markers.zig= captures =mark= plus =(point, start)= per window as
integers at the top of =redraw= and restores in a =defer=. Two transforms:

- =adjustRegion(start, old_len, new_len)= (=:27=) — exact replace semantics
  applied at each row rewrite (=Renderer.zig:977=) and at eviction (=:1071=):
  before the region untouched, inside clamped to the new end, after shifted by
  the delta.
- =pinPos/unpinPos= (=:13-25=) — for resize/reflow the buffer position is
  converted to a libghostty tracked =Pin= before =term.resize= and back after.
  That is how a position survives a *width* reflow, where no arithmetic could.

The README states the principle (=README.org:2433=): the renderer owns the
mechanical consequences of rendering, Elisp owns only policy and intent —
"Elisp should not need to wrap every redraw with ad-hoc marker capture/restore
logic." The test matrix is real: =test/ghostel-render-test.el:210-420= covers
regular redraw, changed-length rows, batched changed-length rows, full redraw,
scrollback row added, *width reflow*, height resize with and without scrollback,
alt-screen resize, and eviction — asserted against semantic tokens, not numbers.

*Does cooked do the Lisp-side patching ghostel calls a mistake? Yes — but with a
different ontology, and the verdict is split.* =cooked--capture-viewport=
(=cooked-render.el:301=) snapshots five things, but they are *intents*, not
offsets:

- =editing= — an *offset into the pending input*, because the input is lifted and
  reinserted verbatim around the cursor on every drain.
- =wandered= — a *screen cell*, because a buffer position would be dragged to the
  start of whatever was rebuilt.
- =follow= — asked of the mode and of where point is, never by comparing point
  against the cursor.
- =others= — the other windows counted as following, decided *before* the
  deletion drags their point along.
- =stale-mark= — and here cooked's own docstring admits the gap: "*the mark gets
  no rescue at all*, only a question asked in time"; =cooked-clear-selection-on-output=
  *drops* the selection rather than relocating it (=:186=).

So cooked's three rescues answer questions =adjustRegion= structurally cannot
("the user was typing mid-line", "the user had walked off the cursor") — a
mechanical transform would silently do the wrong thing for both. But cooked has
*no mechanical layer underneath*, which is exactly why the mark has no rescue,
and why a second window with point in the live screen gets yanked to the cursor
(=cooked--following-windows=, =:227=, treats *any* window with point ≥
screen-start as following) rather than kept where the user left it.
*=adjustRegion= is the missing floor, not a replacement for cooked's intents.*

** The three suspected scroll causes, each with an answer

*(i) Per-char image resolution* — see §2. ghostel's row-range slice is the fix;
the borrowable middle is coalescing *within a row*, which keeps the per-row
independence under scroll that cooked's design note actually names.

*(ii) Long rejoined lines* — ghostel structurally does not have this problem.
=truncate-lines t= plus one buffer line per row means no line is ever longer
than the terminal width, so Emacs' long-line pathologies never arise. It buys
back the semantics rejoining provides (matching a URL split across rows, yanking
without spurious newlines, thing-at-point over a wrapped path) with the
=ghostel-wrap= property plus the bounded join/binary-search pair — paying only
where something actually asks, rather than on every redisplay of every row.

*(iii) mouse-face repaint count* — four distinct things, all cheap to steal:

1. *Text properties, never overlays.* =ghostel--linkify= (=links.el:407=) uses
   =add-text-properties=. cooked's OSC 8 path does the same, but its *detected
   URL* path goes through =goto-address-fontify-region= (=cooked-link.el:350=),
   which creates *overlays* carrying =mouse-face=. Overlays on live rows are the
   expensive form: redisplay assembles the overlay list per window per
   redisplay, and =note_mouse_highlight= walks =overlays_at= on every motion.
2. *The cursor's line and the prompt are excluded from linkification*
   (=ghostel--skip-match-p=, =links.el:464=) — precisely the row a spinner or
   prompt rewrites 30–125 times a second.
3. *Re-application is gated on the text having changed* — same function, a
   fragment already carrying a link id whose stored text still =equal=s the
   match is left alone, so =mouse_face_beg/end= is not invalidated. *This one
   does not transfer.* cooked repaints a row by deleting it and reinserting it,
   so there is no surviving text for a stored match to be compared against, and
   the scrollback — the one place text does survive — is scanned once and never
   re-marked unfontified. The case it fixes, a spinner rescanned every frame,
   cooked answers instead by declining the cursor's row and the prompt outright.
4. *The scan is off the redraw path entirely* — the renderer publishes the exact
   rewritten range (=Renderer.zig:62=, =:867=, =:185=) and Elisp coalesces it
   into markers behind a 0.1 s timer. The README quantifies it: *75 MB/s plain
   ASCII with detection on vs 76 MB/s off*, and 36 vs 78 MB/s on URL-dense
   output — the cost appears only when there is something to find.

cooked instead runs the scan from jit-lock, *inside redisplay*
(=cooked--sync-fontification=, =cooked.el:1369=). That has a genuine advantage —
only /visible/ text is ever scanned, where ghostel scans every repainted row
including ones a flood pushed past the viewport — but it puts the scan, the
overlay creation, and =bounds-of-thing-at-point= per match inside the redisplay
cycle being measured, and it forces registration of =jit-lock-after-change= on
=after-change-functions=.

Two smaller items: =help-echo= is a plain *string* in ghostel
(=Renderer.zig:334=) where cooked's OSC 8 uses a *function*
(=cooked-link.el:289=) evaluated by redisplay on every motion over the span —
and the value is constant per span, so it can be precomputed. And
=ghostel-mode= sets =auto-hscroll-mode nil= and =default-text-properties nil=
buffer-locally (=ghostel.el:4986=, =:4993=), the latter specifically so a global
=line-spacing/line-height= fallback cannot invisibly inflate row geometry.
cooked sets neither.

** Ranked borrowables

1. *Bind =inhibit-modification-hooks= across the property-application phase.*
   The style-span walk, =cooked--apply-deco=, =cooked--render-link-spans=;
   leave =insert=/=delete-region= outside it. *Not* because the rewrite is
   load-bearing for detection — it is not, and that was checked rather than
   assumed. Emacs' =insert= inherits no text properties, so a rewritten row
   carries no =fontified= property by construction and reads as unfontified
   whether or not =jit-lock-after-change= ever ran; a blanket inhibit across
   =cooked--render-block=, across =cooked--render-rows=, and across the whole of
   =cooked--apply= by advice each left the suite green and each left a URL
   straddling the scrollback seam still linkified. The rewrite stays outside for
   two other reasons: the saving is entirely in the loops, so there is nothing to
   buy by moving the line, and a change hook a user has added is entitled to see
   the edit. The one place the notification really *is* the mechanism is a
   *property-only* update over surviving text, where =put-text-property= is what
   marks the text unfontified — see =cooked--rescale-deco=, which inhibits it
   deliberately because there the rescan is the waste (+28% on the walk) rather
   than the point.

   *The +21%/+55% figure does not belong to this item* and was borrowed in
   error: it is =cooked--sync-fontification='s own docstring's, measured for
   dropping the jit-lock *registration* with =cooked--fontify-region= never once
   called. Measured for the binding itself, interleaved A/B: primary screen
   −36.4% styled, −8.6% box, 0.0% plain; alternate screen −20.2%, −3.7%, 0.0%.
   About half survives on the alt screen even with no Lisp hook attached,
   because the binding also short-circuits Emacs' own
   =prepare_to_modify_buffer=/=signal_after_change= bookkeeping. Plain rows gain
   nothing and cannot — they carry no style spans, so nothing runs inside the
   binding.
2. *Coalesce adjacent damaged rows into one =delete-region= + =insert=*, with
   face runs crossing row boundaries. =Screen::drain_damage= already returns
   ascending indices and =Update::scrolled_rows= already assembles many rows
   into one =Block=, so the machinery exists. A 45-row repaint goes from 45+45
   buffer edits to ~1+1. Cost: per-row =WIDTH/ASCII= scalars become vectors so
   =cooked--guard-row-width= still gets a per-row answer.
3. *Coalesce image =display= within a row* (§2 item 1).
4. *Replace =goto-address-fontify-region= overlays with text properties* —
   cooked already has =cooked-link--propertize= and a =cooked-link-id= property
   for ownership detection, so the detected-URL path can use the same mechanism
   and drop the overlay list from every live row.
5. *Skip linkification of the cursor's row and the prompt; gate re-application
   on the text having changed.*
6. *Skip the drain for a buffer no window shows*, flushing from
   =pre-redisplay-functions= when it becomes visible. Caveat: cooked's buffer
   /is/ the scrollback, so deferral must not lose evicted rows — the
   =:scrolled= block would have to accumulate across skipped wakes, or the skip
   apply only to live-screen rows. A hidden =make -j= currently costs cooked a
   full apply per 8 ms and ghostel nothing. (cooked was right to remove its
   =pre-redisplay-functions= hook for /pinning/ — the 202 MB vs 28.7 MB
   measurement — but a hook that checks one buffer-local flag and usually
   returns is a different animal.)
7. *=adjustRegion= as a mechanical floor under the intent layer.*
   =cooked--render-rows= knows =(old-start, old-len, new-len)= for every row it
   rewrites, so the transform is cheap in Lisp. Apply it to (a) the *mark*, which
   today is simply deactivated, and (b) the =window-point= of other windows in
   the live screen that are not semantically following. Keep
   =editing/wandered/follow= exactly as they are.
8. *A redisplay-inclusive benchmark mode* — see §9. =tests/cooked-bench.el='s
   own header says batch mode measures spec construction and property
   application, *not rasterization*. Since the ceiling is attributed to
   redisplay and every current number excludes it, this is the instrument the
   investigation is missing. None of the three suspects will move a batch
   benchmark.
9. Small buffer-locals: =auto-hscroll-mode nil=, =default-text-properties nil=.
10. Precompute =cooked--link-help-echo= into a string where the destination is
    static.

** The highest-information measurement available right now

The three suspects are *not independent*. =cooked-rejoin-wrapped-lines= = t is

Three findings that bear directly on cooked:

1. *ghostel is the only implementation in the set with a per-event bypass*, and it
   exists to undo a 33 ms Elisp timer that libghostty-vt's own owner never had.
   Adding an eager path is not catching up to the field — it is going past it, and
   deserves matching suspicion.
2. *Everyone pays an anti-flicker hold on echo, and the constants cluster
   tightly* — foot 0.5 ms renewed + 8.3 ms, st 2 ms decaying, kitty 3 ms,
   wezterm 3 ms, xterm read-until-quiet + 25 ms. **cooked's =QUIESCENCE= is
   foot's rule with foot's numbers.** This gate has the strongest
   cross-implementation mandate of anything surveyed.
3. *The real floor is display backpressure, not a clock* — WT's
   presentation-released waitable, ghostty's DisplayLink, foot's Wayland frame
   callback, alacritty's =RedrawRequested=. cooked already has this *in the
   strongest form*: the token is released when Emacs reports the frame **drawn**,
   not when it submits. And where the field does express input priority it is as
   *scheduling* priority (vte's idle-priority repeat, xterm's event peek,
   iTerm2's rate drop) — never as a bypass of the anti-tearing wait.

** The recommendation: waive =min_interval=, never =QUIESCENCE=

Scope an eager path to the one gate with no evidence behind it, gate it on an
echo window opened by the write choke point and *consumed by the first read that
follows*, and classify at the choke point using what Emacs already knows.

*Why =QUIESCENCE= stays.* It is the gate the whole field agrees on and the only
policy in the tree that waits on a *client* rather than a clock. Echo is the most
tearing-prone write there is — the thing echoing is usually readline or a TUI
redrawing a line across several =write(2)=s, in the one screen region the user is
staring at — and st's config comment names exactly the failure on offer. The
prize is 500 µs: three orders of magnitude below perception, and 6% of the 8 ms
actually worth recovering. Highest cost, lowest benefit.

*Why =min_interval= goes.* A pure clock, the only gate in =flush= with no
cross-implementation evidence, and the one that bites the real case.
=DESIGN.md='s defence — "a keystroke echoed after a quiet moment passes every
gate on the spot, the throttle having long since elapsed" — is correct *and* is
the limit of the argument: it holds only while =state.last= is stale. Typing into
active output is worth up to a full 8 ms, which against the 33–88 ms end-to-end
figures Chad Austin measured on Windows is 10–25% of the visible budget.

*Why the waiver cannot run away here*, for two reasons specific to cooked:
=notified= means at most one wake is ever in flight, and =rearm= does not fire
until Emacs reports the frame *drawn*. Removing an 8 ms clock from a pipeline
whose real limiter is a 0.16–11.9 ms render acknowledged by the consumer cannot
produce a runaway — and =DESIGN.md='s own 40-applies-against-91-redisplays
measurement is the proof. This is Windows Terminal's =SetMaximumFrameLatency(1)=
argument, and cooked's version is stronger because the ack comes from the draw
rather than the submit.

*** Classification without losing the choke point

The write path's single-door property is worth keeping and can be kept, because
cooked's FFI boundary already splits the traffic:

- =reply_osc= (=src/lib.rs:575=) is *already a separate entry point*, so
  automatic replies (DSR, focus) are excluded for free — no flag, no caller
  cooperation.
- =send= (=src/lib.rs:560=) holds an =emacs_env=, so the classifier can *ask
  Emacs* rather than inspect bytes: is the event being dispatched a mouse event?
  One funcall against =last-input-event=. That correctly excludes wheel notches,
  drag motion under =track-mouse=, and crucially *alternate scroll*, which byte
  inspection cannot distinguish from arrow keys because =cooked--alt-scroll-keys=
  emits literal cursor keys.
- Cheaper fallback if a funcall on the write path is unwelcome: an O(1) prefix
  test for =ESC [ M= and =ESC [ <=, matching what =cooked--mouse-report= emits.
  Covers press/release/motion, misses only alternate scroll.

Either way the flag is computed *inside* =lib.rs::send=, so no Lisp caller gains
a parameter and no future input path can forget one. And note the failure
*direction* if an opt-out is ever added: a flag defaulting to "not eager" fails
toward today's latency — a regression in feel, never a lost write or a torn
frame.

*** The window: opened by the write, closed by the first read

Not distinguishable at the byte level, and worth not trying. Instead
=Session::send= records =echo_until = now + ECHO_WINDOW=; the first =fed()= that
registers a drawable change consumes it with =Option::take=, converting it into a
*one-shot* waiver for the frame being assembled. That buys exactly one waived
frame per write (so key-repeat at 30/s buys at most 30, each still bounded by the
drawn-ack), self-decay so a keystroke into a program that never echoes leaves no
latent waiver, and no pattern matching or per-frame state beyond one
=Option<Instant>=.

=ECHO_WINDOW= wants 50 ms — the same number ghostel chose, and half of
=INTERACTION_WINDOW=. The one-read consumption is what makes 50 ms safe;
ghostel's is time-only, so under key-repeat its bypass is effectively always on.

*** Sketch

All in =src/session.rs= but one classifier line in =src/lib.rs=:

#+begin_src rust
/// How long after a keystroke the first frame may skip `min_interval`.
const ECHO_WINDOW: std::time::Duration = std::time::Duration::from_millis(50);

// NotifyState, two self-retiring fields:
echo_until: Option<std::time::Instant>,  // set by expect_echo, taken by the first read
echo: bool,                              // this frame is one a keystroke waits on

// flush(), the only behavioural change:
if !state.echo && state.last.is_some_and(|t| t.elapsed() < state.min_interval) {
    return true;
}
// ...and clear `echo` beside `ceiling_at`/`held_since` when the flush sends.
#+end_src

=expect_echo()= is called from the same place =interacted()= is, preserving the
single-write-path property — *with one refactor hazard*: =interacted()= returns
early when =attended=, so =expect_echo= must sit before that return.
=poll_wait= needs no change but should be checked: an echo frame no longer waits
on the throttle window, so the retry it schedules is redundant rather than wrong.

*** The docstring this amends

=DESIGN.md= "The pace is a floor, not a clock" currently asserts there is no
urgent path and argues an exception would buy nothing. That argument is sound for
=QUIESCENCE= and sound for the idle-prompt case, and wrong for exactly one case:
typing into active output, where =state.last= is fresh. The amendment should say
that and keep the rest, because the rest is the reason not to waive more.

*** Failure modes to test

- *A floor that never engages* — the bug the =rearm=/=ready= split exists to
  prevent, reintroduced from the other end if =echo= is armed and never cleared.
  Guards: =take()= on consumption, =remaining()= on the deadline. Test: hold a
  key under =yes= output and assert the wake count tracks *redisplays*, not
  *writes*.
- *Tearing* — regression-test =getpass= and a readline line-redraw, asserting the
  500 µs hold is still paid on echoed frames.
- *Priority inversion under a flood* — more wakes of smaller deltas each pay
  drain + apply overhead. If throughput drops materially with a key held, the fix
  is to bound the waiver (one per =min_interval=), not remove it. vte's
  idle-priority repeat and iTerm2's rate drop are the two established answers.
- *Mouse-motion spam* — test a 1003 sweep and a wheel gesture in =less=; the wake
  rate must be unchanged. The byte-prefix classifier misses alternate scroll, so
  measure that case specifically if the cheap route is taken.
- *Classifier staleness* — =last-input-event= is stale when =cooked--send= runs
  from a timer or filter (shell completion, deferred replies). Rare and
  user-initiated, so a stray waiver is harmless, but worth a docstring line so
  the classification is not taken for stronger than it is.

*** What to measure, and the expected numbers

| Measurement                                        | Expected                                                                                                      |
|----------------------------------------------------+---------------------------------------------------------------------------------------------------------------|
| echo latency, typing into active output            | today roughly uniform on 0.5–8.5 ms; should collapse to ~0.5–1 ms plus one read turnaround. Mean saving ~4 ms |
| echo latency at an idle prompt                     | *unchanged* — a change here means the waiver fires where nothing needed fixing                               |
| wake count/s under flood, key idle vs held         | within the same order as today's 40 applies / 91 redisplays                                                   |

window and leave the pace alone.

** What cooked does better

The pacing model (four gates with Emacs' own completion as the retirement
signal, versus three tuning knobs approximating it) · *DEC 2026 with a 150 ms
deadline*, where ghostel has none and a misbehaving child freezes the display ·
quiescence + two independent ceilings, with the =ceiling_at=-armed-on-the-second-change
refinement that avoids drawing a cursor onto a half-arrived picture ·
backpressure as a separate concept from pacing ("one paces, the other pauses") ·
the packed wire protocol and the memoized face cache (ghostel has neither) ·
carried row geometry, with the asymmetry argument for caching only the "this
wraps" direction · jumping to damaged rows rather than walking every row ·
hoisting per-drain answers out of the per-row loop (the bug that fixed: two
=select-window= round trips per displayed window per row, with =select-window=
advised by evil) · =cooked--pin-transcript-bottom='s monotone NOFORCE follow
with the equality case writing nothing, and the explicit rejection of =recenter=
— where =ghostel--anchor-window= calls =window-text-pixel-size=,
=set-window-start=, =set-window-vscroll= and =set-window-point= on every
anchored window on every redraw, inside =with-selected-window=, which is the
shape cooked measured and removed · the seam as a single co-owned number with a
debug assertion · =cooked--mark-truncation='s three traps.

** The headline

than sixel at =graphics.rs:255=, so #2 and #7 share a prerequisite. Note ghostel
leaves =TN= unanswered, so cooked can beat it outright by answering the terminal
name from its own terminfo.

** The eval channel — cooked's design is better, and the gap is material

|                   | cooked =OSC 51;E=                                                                                                       | ghostel =OSC 52;e=                                                                               |
|-------------------+-------------------------------------------------------------------------------------------------------------------------+--------------------------------------------------------------------------------------------------|
| enablement        | closed until =(require 'cooked-osc-eval)=; the hook is nil-valued in the core so "not loaded" and "off" cannot disagree | *always on*, five entries by default                                                             |
| wire format       | =OSC 51;E<version>;<verb>[;<arg>]= — versioned, one closed-set letter verb                                             | =OSC 52;e;"a" "b"= — unversioned, first token is a function name                                |
| dispatch          | *closed verb set* =F O D K != ; nothing maps a child string to a function except =!=, whose table is *empty by default* | *name allowlist*: =assoc= then =apply= with the child's strings                                  |
| validation        | each verb is cooked's own code; =cooked--local-name= rejects remote/TRAMP names *before* any =file-directory-p=         | none; =find-file= gets the child's string directly                                               |
| timing            | *deferred* out of the drain, so a verb can prompt and run hooks safely                                                  | *synchronous, inside the VT parser*; a =y-or-n-p= from there recurses the command loop mid-parse |
| failure reporting | refusal messaged *once per buffer*, so a hostile stream cannot spam the echo area                                       | a message per unknown command, unthrottled                                                       |
#+TBLFM: $2=OSC 51;E<version>;<verb>[;<arg>]= — versioned, one closed-set letter verb

The decisive argument is cooked's own: *an allowlist of names settles which
function runs and says nothing about what it is pointed at.* =ghostel-eval-cmds=
ships =find-file= by default, so =ghostel_cmd find-file /ssh:attacker.example:/etc/motd=
is a TRAMP connection to a host the sender chose, reachable from any =cat= of a
hostile file, with no opt-in anywhere. Their README suggests adding
=magit-status-setup-buffer= — which runs git against an attacker-chosen repo,
honouring its =core.fsmonitor=.

Two things borrowable *into* cooked anyway: the multi-argument quoted payload
(the one-arg-verbatim rule is elegant but forecloses verbs like
=("goto-line" FILE LINE)=; the =!= verb already uses
=split-string-and-unquote=, so the shape exists), and =ghostel_cmd= as a single
shell-side helper, cleaner than per-verb aliases for scripting.

** Colour scheme and palette

Both arrived at the same architecture independently: Emacs classifies its own
background with =color-dark-p=, hands the answer to the core, the core answers
=CSI ?996 n=, and a theme change pushes an unsolicited =CSI ?997= to mode-2031
subscribers. Two real differences:

- *Consistency between 996 and OSC 11.* cooked derives the scheme from the same
  value OSC 11 answers with, specifically so a child that hears "scheme changed"
  and then queries OSC 11 cannot get two contradicting readings. ghostel's
  README states the opposite as a feature — a child's OSC 11 override does not
  change the 996 classification, but it /does/ change what OSC 11 replies, so
  after a child set the two disagree.
- *Palette.* cooked maps 0–15 onto Emacs' own =ansi-color-*= faces and declines
  OSC 4 entirely, on the grounds that a per-buffer 256-entry palette is the wrong
  seam. ghostel defines =ghostel-color-*= faces and pushes the resolved hex
  values *into libghostty's palette*, which is what makes its OSC 4 query answer
  correct and lets anything on =termenv= auto-detect from Emacs faces. *cooked's
  face story is better* (themes that style =ansi-color-*= work with no
  configuration); *ghostel's wire story is better* (OSC 4 actually answers).
  Item 4 above closes that without giving up the face story.

** Terminfo

ghostel ships ghostty's bundled =xterm-ghostty= and claims
=TERM_PROGRAM=ghostty= — inheriting a capability list belonging to another
program, minus a hand-removed =Ms=. cooked writes =cooked-256color= out in full
rather than with =use=xterm-256color=, precisely because =use== claims
everything xterm has plus everything ncurses adds later; the file documents each
removal and addition, and *DECRQM answers 4 for every mode named as removed*, so
the claim is machine-auditable. Strictly the better approach; keep it.

Two mechanisms on ghostel's side worth taking, both also flagged in §5:

- *=ghostel--push-remote-terminfo=* (=ghostel-shell.el:375=) — pushes the
  compiled entry into a remote temp dir over TRAMP, writing *both* the =x/= and
  =78/= subdirectory layouts so remote ncurses or BSD libcurses finds it, exports
  =TERMINFO=<tmpdir>=, and cleans up. cooked's =cooked-install-terminfo-remote=
  needs an interactive host argument and installs permanently under
  =~/.terminfo= on the far end.
- *The ssh wrapper* (=etc/shell/ghostel.bash:256-365=) — resolves the canonical
  target with =ssh -G=, *caches the outcome keyed on a =cksum= of the local
  entry* so a terminfo bump auto-invalidates, installs with
  =infocmp -0 -x | ssh … tic=, falls back to =xterm-256color= with a message,
  mkdir-as-lock so two buffers don't race, and has a =KEEP_TERM=1= escape hatch.
  Only relevant if cooked advertises a non-universal =TERM= — check what it
  actually sets first. The cache-key-includes-local-hash idea is the part worth
  copying.

** Also cooked's, on this axis

Every query answerable is answered, refusals included · one reply framer with
one safety rule · the extension seam in *Lisp, not Zig* — every unclaimed OSC
arrives as =Event::Osc= and a new integration is one alist entry, with the two

* 9. Benchmarks and test infrastructure

:AXIS: measurement methodology, property testing, CI mechanics
:END:

** Two corrections to earlier framing

*=lisp/ghostel-debug.el= is not a debug-adapter integration.* It is 2079 lines
of diagnostic logging and bug-report generation — no DAP, nothing to do with
debugging a debuggee in a terminal. The DAP-adjacent file is
=tools/ghostel-dape.el=, a *developer* tool (217 lines) that launches a batch
Emacs under =lldb-dap= so you can debug the native module while an ERT test or a
saved Hypothesis case runs inside it.

*ghostel's bench numbers are not CI-tracked.* No perf job, no committed
baseline, no threshold that fails a build. The README tables are hand-transcribed
from local runs on one machine. What is transferable is the *harness*, not a
regression-tracking story that does not exist.

** The timing core — the piece to steal verbatim

=ghostel-bench--measure= (=bench/ghostel-bench.el:270=):

1. =garbage-collect=
2. *one un-timed warmup call*
3. =garbage-collect= again
4. a *trial phase*: =min(3, iterations)= timed iterations to estimate per-iteration cost
5. if the trial came in under =ghostel-bench-min-duration= (0.5 s), raise the
   count to =ceiling(min-duration × trial-iters / trial-time)= — *the declared
   =iterations= is a floor, never a ceiling*
6. =garbage-collect= a third time
7. the measured loop, continuing *while either* the count is unmet *or* elapsed
   < =min-duration= — so a case that got faster than the estimate still runs
   long enough to time
8. report iterations, total, per-iter ms, and MB/s

Timer is =float-time= deltas, not =benchmark-run= — a deliberate fit, because
=benchmark-run= cannot express "keep iterating until the clock says we have
enough". *Mean only, no percentiles*, except in typing latency.

*GC handling is three distinct layers.* Around a measurement: =garbage-collect=
three times, but *not* suppressed during the loop — a flood that allocated its
way into a collection should pay for it, because a real session does. Inside
synthetic renderer measurements: =ghostel-bench--redraw= (=:93=) pins
=gc-cons-threshold= and the same inhibits production uses, because a synthetic
number that /didn't/ would measure overhead production suppresses and be
pessimistic in a way the user never experiences. In typing latency: one
=garbage-collect= up front, then the threshold raised to ≥256 MB for the whole
run so a stray collection cannot land inside one keystroke and blow out the p99.

*Redisplay isolation, honest in both directions.*
=ghostel-bench--with-bench-buffer= (=:241=) =set-window-buffer=s the temp buffer
into the selected window — batch's selected window is non-displaying, but
=get-buffer-window-list= still returns it, which is enough to make the
window-dependent parts of the redraw path actually execute rather than
short-circuit. And =ghostel-bench-force-gui-redisplay= (=:64=) calls
=(redisplay t)= after each iteration — *off by default*, existing for GUI
profiling runs. So the default is "parse + buffer mutation, no redisplay", with
an explicit opt-in, never mixed silently.

** The three published numbers

*Native vs Emacs PTY.* For each of two data shapes, =ghostel-bench--measure=
wraps a real =cat= spawn with =ghostel-use-native-pty= t then nil, and prints the
ratio directly. Both legs real PTY, full pipeline, real spawn per iteration, so
it isolates *only* PTY ownership.

*Burst absorption* (the 10 MB =cat= table). Stated as "median of five" — but the
harness reports *mean*, so that table was assembled by hand. The prose does the
more important work: the wall clock is half the story, because vterm and eat
parse on the main thread so Emacs is frozen for the *entire* transfer. That
qualitative claim is measured by nothing in the suite.

*Typing latency* (=:1683=) — the clever one, and the best idea in the file.
Measuring keystroke→pixel latency in batch looks impossible; the trick is three
parts:

1. *A child that echoes one byte per byte, unbuffered*:
   =sh -c "stty raw -echo; printf READY; exec cat"=. =raw= kills the line
   discipline so a single character round-trips immediately; =-echo= means the
   only echo is =cat='s own. Spin until =READY= appears before starting.
2. *=buffer-chars-modified-tick= as the arrival detector.* Searching the buffer
   would be O(buffer size) and the cost would creep into the measurement as text
   accumulates over 1000 keystrokes. Instead: snapshot the tick, send, spin
   =accept-process-output PROC 0.001= until it changes. O(1), unaffected by
   wrapping or buffer growth.
3. *30 discarded warmup keystrokes* to prime trampolines and redraw caches, then
   GC pinned for the 1000 recorded samples.

Report: n, *min, median, p99, max*. The only distribution in the suite, and
correctly so. The docstring also names the one place the backend ordering
*inverts* relative to throughput — the native path's background-thread read
signals Emacs through an event pipe, so a single tiny echo carries an extra IPC
hop the main-thread filter does not pay. *A suite that only reported throughput
would have published a straight lie about interactivity.*

** Fixtures and scenarios worth noting

Generators, not recordings. Two carry methodology comments worth copying: the
URL/path generator deliberately puts paths *outside =/home=*, because macOS maps
that through autofs where a =file-exists-p= miss costs ~8 ms and swamps the scan;
and the wrapped-link generator uses a *rotating indent* (=% n 11=) so soft-wrap
breaks land at many different offsets inside the links rather than always the
same one.

The =tui-partial= scenario (=:1034=) renders a static screen *once*, then
rewrites only the bottom row per iteration — added explicitly because
=tui-frame= (every row per frame) cannot distinguish dirty-row tracking from
unconditional re-render. It is how they found the per-row dirty-bit branch is
*8–13× faster* than full mode. That is the status-bar/prompt-redraw workload,
and cooked has no equivalent.

=ghostel-bench-cases= (=:1455=) is a flat list of 33 named cases with
=ghostel-bench-run-one= dispatching one — which is what turns a benchmark suite
into a debugging instrument.

** Where cooked stands

cooked has three measurement surfaces, each good at something ghostel's is not:

- *=tests/throughput.rs=* — one shot per case, no warmup or iteration, *but it
  models the reader loop's backpressure*: chunks at =READ_CHUNK=, samples
  =term.backlog()= between chunks, forces a drain at the high-water mark, and
  reports "N rows backlogged, M drains forced by backpressure" alongside
  throughput. A more sophisticated fixture than anything in ghostel's engine
  section.
- *=tests/cooked-bench.el=* — two well-reasoned tiers. Tier one drives a real
  child and times only drain+apply inside the =accept-process-output= loop, so
  the child's own runtime is correctly excluded. Tier two hand-builds the packed
  wire records and calls =cooked--apply= one frame at a time against a sleeping
  child, precisely because damage coalescing makes 400 repaint frames arrive as
  four drains. The commentary around it is *better reasoning about measurement*
  than anything in ghostel — it explicitly refuses to let the RATIO=8 figure be
  read as a claim about a live session, and cites the 40-applies-per-91-redisplays
  measurement to say why.
- *=tests/cooked-tests-bench.el=* — ERT tests pointed at the *benchmark's own
  fixtures*, checking hand-packed records against the reader's stride, written
  because both fixtures had already gone stale once and "a fixture that goes
  wrong more quietly would simply have reported a plausible number for work the
  renderer never does." *ghostel has no equivalent and should.* This is cooked's
  own best benchmarking idea — keep it.

Missing, concretely: warmup · iteration with auto-scaling · explicit GC
discipline · any distribution (everything is a single total) · named addressable
cases · a self-describing run header · typing latency · a window attached to the
bench buffer · any load-sensitivity guard (*neither project has one*).

** The plan for cooked's bench suite

*A. One measured primitive.* =cooked-bench--measure (label unit-count body-fn)=,
with ghostel's semantics exactly: one discarded warmup, =garbage-collect= three
times, a 3-iteration trial raising the count to hit =min-duration= with the
declared count as a floor, loop while =(or (< done n) (< elapsed min-duration))=.
Then *diverge in one respect*: keep every per-iteration time in a list, not just
the total, and report min/median/p99/max *and* mean. ghostel does this only for
typing latency; there is no reason the flood and per-frame numbers should not
carry a spread, and the spread is what tells you whether to believe the run.

For the synthetic tiers add a =cooked-bench--with-render-bindings= analogue
pinning =gc-cons-threshold= and the inhibits as production does. Do *not* pin it
in the real-child benchmarks — a flood should pay for its own garbage.

One correction to what "as production does" means here, since it reads as
cooked's: it is *ghostel's*. §7 records ghostel binding =gc-cons-threshold
most-positive-fixnum= around its whole native redraw (=ghostel.el:4645-4649=);
cooked binds it nowhere. So the honest question is not how to reproduce it in a
benchmark but whether cooked should be doing it at all — and, measured, it
should not. Bracketing =cooked--apply= in =(let ((gc-cons-threshold
most-positive-fixnum)) …)= does keep collection out of the apply, styled p99
18.8 → 1.5 ms; but the collection then lands at the *unbind*, microseconds later
and still before the frame reaches the screen, so p99 across the whole bracket
is 21.2 ms. It is moved, not deferred. It also costs 112 collections against 71
and 20% more wall, and at an interactive =gc-cons-percentage= of 0.1 it forces a
collection on *every* unbind — 1500 against 0 over 3000 frames, in both arm
orders. Emacs' watcher on the variable recomputes the collection budget on the
restore, against consing already done. A session-wide raise is the only form
that works, and that is a policy change rather than a redraw binding.

*B. Attach a window.* =cooked-bench--with-session= already fakes a cell size;
add the =set-window-buffer=. cooked has bottom-anchoring and sticky-scroll paths
that consult the window, and if they are short-circuiting in batch the numbers
measure less than production does. Diff a run before and after to find out.

*C. Typing latency — the highest-value missing benchmark.* cooked's entire bench
surface is throughput and per-frame cost, and neither predicts interactive feel;
the scroll-ceiling work is a *latency* problem no current number can see. Port
the =buffer-chars-modified-tick= trick with two cooked-specific adaptations:
cooked drains explicitly rather than through a process filter, so the spin loop
calls =cooked--apply (cooked--drain …)= — which means you are measuring
send→drained-and-applied rather than send→filter-fired, which is *strictly more
informative* than ghostel's version. And run it in *three* configurations —
plain, with box-drawing decoration on the echoed row, and with =mouse-face= in
play — because the value is catching regressions in exactly the decoration and
repaint paths throughput cannot see.

*D. Keep it honest — two independent guards.*

Before the run, refuse a busy machine:

#+begin_src elisp
(defun cooked-bench--load-ok-p ()
  "Non-nil when 1-minute load is low enough to trust a timing result."
  (condition-case nil
      (let ((one-minute (/ (car (load-average)) 100.0))
            (cpus (num-processors)))
        (< one-minute (* 0.5 cpus)))
    (error t)))                         ; can't tell -> don't block
#+end_src

Print the measured load in the header unconditionally and refuse to run unless
=COOKED_BENCH_FORCE= is set. Two subtleties: 1-minute load lags by design, so a
run started 20 s after a big build still reads high — that is the conservative
direction and it is fine; and the benchmark's own children raise the load, so
sample once at the start and do not re-check mid-run.

After each case, refuse an unstable result — this is the check that catches
interference starting *during* the run, which loadavg cannot:

#+begin_src elisp
;; Over the *collection-free* samples only.  p99 against the median of
;; everything fires on 8 of 18 rows on a perfectly quiet machine, purely on GC.
(when (and (>= (length clean) 3) (> p99 (* 3 median)))
  (message "  %-42s UNSTABLE (p99 %.1fx median over %d gc-free samples) -- rerun"
           label ratio (length clean)))
#+end_src

Mark the row loudly rather than failing. Better than a wall-clock threshold
because it needs no per-machine calibration — it is self-relative.

Two things learned applying it. First, *the 8-of-18 figure is partly the
harness's own fault*: =make bench= has no =compile= prerequisite and the
=compile= target deletes its own =.elc=, so every number in the suite is
measured on interpreted Lisp nobody runs. Byte-compiled, a styled frame conses
1,858 cells against 14,112, per-frame styled p50 goes 0.575 → 0.183 ms, and the
literal rule fires on *3* rows rather than 8. Fix the harness before filtering
the tail away. Second, and in the other direction: *the ratio check cannot catch
what loadavg can*. A uniform slowdown moves median and p99 together and divides
out — under forty spinners the styled median went 0.6 → 7.5 ms with the ratio
barely moving. The two guards are complementary in *both* directions, not one
covering for the other. Pair it with
*reporting medians, not means, as the headline for every case*: the mean is what
one interfering scheduler event destroys. ghostel reports means everywhere
except typing latency and is worse for it.

*E. Name the cases.* =cooked-bench-cases= + =cooked-bench-run-one= —
=flood/plain=, =repaint/box=, =per-frame/24x80/styled=, =deferred/url/8=,
=typing/box=. The payoff is not about benchmarking: it makes
=perf record -- emacs -Q --batch --eval '(cooked-bench-run-one "repaint/box")'=
a one-liner, which is exactly what the scroll-ceiling investigation needs. No
xctrace wrapper required on Linux.

*F. Add =make bench-quick=.* =make bench= currently runs the whole Rust suite
plus every Elisp benchmark with no fast path, so it does not get run, so drift
is not noticed. Under ten seconds is the difference between a suite you run
before committing and one you do not.

*G. One fixture to add.* The rotating-indent wrapped-link generator, which
targets suspect (ii) directly. And steal the =/home=-avoidance discipline for
anything that triggers =file-exists-p=, since cooked has a file-link layer.

*H. Skip the cross-emulator =e2e= section* unless you want the number for the
README. High harness cost (package discovery across four install layouts,
per-backend encoding rules, four constructors, four filter drivers) for
marketing rather than engineering — you cannot profile vterm's internals from
here, so the comparison guides no optimization.

** Property-based testing: the harness, and the cheaper version for cooked

*The property is one line and it is exactly right*: after any sequence of
writes, resizes and incremental redraws, *a full redraw must not change the
buffer's text* (=test_render.py:1253=). That is a *self-oracle* — no reference
implementation, no expected output to maintain. For a dirty-row-tracking
renderer it catches the entire class of "the incremental path missed a change",
which is the hardest class to find by hand and the most damaging in practice.

Mechanics worth knowing: one *long-lived batch Emacs* spoken to over JSON lines,
because shrinking needs hundreds of replays and spawning Emacs per case makes
that impractical; base64 for all byte data so invalid UTF-8 fragments survive
the round trip; a *daemon thread* draining stderr into a 200-line deque so a
module panic reaches the failure message; a deadline on reads so a hang becomes
a =TimeoutError= with the stderr tail attached rather than a wedged run.

Generator design, five layers, and three details are load-bearing:

- *Relative resize deltas*, clamped to ≥1 — so a shrunk case stays valid when
  the initial size shrinks too.
- *The =fragmented= motif*: a complete escape split across 1–4 writes at random
  byte offsets. This is the parser-state-across-read-boundary bug class, the one
  a naive fuzzer never finds. Plus =alt_screen_cycle= with a resize *while on
  the alt screen*, and =save_resize_restore= (save cursor, resize, write,
  restore) — both notorious divergence sources.
- *Capped =target()= metrics* — nine of them, each =min(actual, ceiling)=.
  Uncapped, =target()= pushes toward ever-larger inputs that are slower and
  shrink worse; capped, it pushes toward *complexity up to a ceiling and no
  further*.

And the loop is closed: shrink → write artifacts *only from the final shrunk
case* → commit it as =cases/render-<hash>.json= → replay the corpus as a fast
deterministic suite → =ghostel-hypothesis-replay-file= runs one case in batch
for a native debugger. Failure messages carry a first-difference visualization
(offset, line/col in both snapshots, a label for the differing char, ±120 chars
of context).

*For cooked, do the Rust version first.* cooked's architecture makes this easier
than ghostel's and the property even more load-bearing, because there are *two*
self-oracles available:

1. *Rust-side, no Emacs at all*: feed a generated op sequence, then assert that
   replaying the accumulated deltas onto a model grid equals the term's own full
   grid. A =proptest= target in =tests/=, thousands of cases per second, no IPC,
   shrinks natively. *Do this one first* — a few hours, and it covers the parser
   and the damage tracker, which is where the subtle bugs are.
2. *Emacs-side, the full property*: ops → incremental =cooked--apply= → text;
   full redraw → text; assert equal. Covers =cooked--render-block=, the span
   decoders, and line rejoining. Needs the long-lived-process arrangement.

Take: the single self-oracle property, relative resize deltas, the
fragmented-write motif (for cooked this is directly the =READ_CHUNK= boundary,
and given cooked drains on a wake byte it is the highest-yield motif of the
lot), alt-screen-cycle-with-resize, save/resize/restore, capped =target()=, the
committed shrunk corpus, the first-difference visualization, 1-row and 1-column
sizes and 0/1-byte scrollback as first-class generated values, and the stderr
tail so a Rust panic surfaces.

*Add, because cooked has surfaces ghostel does not*: generate
=cooked-rejoin-wrapped-lines= *both ways* (it is a text-identity transformation,
which is exactly what a consistency property checks — and it is suspect (ii));
generate box-drawing runs so the deco spans get fuzzed; generate OSC 66.

*Skip Python and Hypothesis initially.* The harness is excellent and Hypothesis
shrinks better than proptest, but a Python dependency plus a JSON protocol plus
an Elisp driver is three moving parts for a solo project, and the highest-value
property needs none of them. Add the Emacs-side property only if the Rust one
stops finding things — and then drive batch Emacs from Rust rather than adding
Python.

** Makefile and CI mechanics worth adopting

- *ERT tags as the platform/dependency axis.* =run-elisp= selects
  =(and (not (tag native)) (not (tag windows)))=, =run-native= the complement.
  So =make test= runs on a machine with no toolchain at all, and CI byte-compiles
  and runs pure-Elisp tests across three Emacs versions without building the
  module. For cooked the tag axis is the more valuable half: cooked's
  =skip-unless= on optional packages already reads as passing when it skips, and
  the =cooked-tests--optional-packages= load-time report exists because of
  exactly that. Tags make it structural — "this suite ran zero evil tests"
  becomes a target that was not invoked rather than a line in the output tail.
- *Per-file stamp targets for parallelism.* 33 test files → 33
  =.build/tests/{elisp,native}-%.ok= stamps, each depending on the test file,
  the helpers, the =.elc= set, and the module artifact — which is a *real file
  target*, not phony, so Zig source mtimes decide whether tests rerun. =make -j=
  then floors at the slowest single file rather than the sum. cooked's
  =cooked-tests.el= already documents running one subject file directly, so the
  files are independently loadable and the split is mechanical.
- *An mtime trap fixed explicitly*: the =lisp/%.elc: lisp/%.el= pattern rule
  exists because Emacs prefers a stale =.elc= over a newer =.el=, silently
  masking edits.
- *=GHOSTEL_TEST_TIMEOUT_SCALE=*, defaulting to *4 when =CI= is set*. The
  parsing is defensive in a way that reads as learned the hard way: =getenv=
  returns ="= for a set-but-empty var and =string-to-number= maps ="= and
  garbage to 0, which would zero every timeout and fail every wait instantly —
  so *only a positive numeric parse is accepted*. Sound justification: the waits
  early-exit the moment their predicate holds, so a larger ceiling costs nothing
  on a passing run.
- *=GHOSTEL_DEBUG_TESTS=* — =:before= advice on =ert-run-test= messaging each
  test name synchronously, so the last printed line is the test that hung or
  crashed. Fifteen minutes' work, invaluable when a native module dies in batch.
- *Two wait primitives with different failure messages*, both distinguishing
  "timed out with the process alive" from "the process exited before the
  predicate succeeded" — with a 1-second grace after death, because a child's
  exit is visible via =process-live-p= before its sentinel has run.
- *A PTY matrix helper* running one body once per backend with =ert-info=
  carrying the backend name into failure output.
- *Python-child fixtures* (=test/fixtures/pty_setup.py= plus inline raw-PTY
  scripts) giving exact-byte assertions on the input encoder with no line
  discipline in between. Directly applicable to cooked's large =cooked-keys.el=.
- *A tiny custom lint*: =docquotes=, 15 lines of regexp catching
  =`[A-Z_]+'= — melpazoid's rule widened to catch =INSIDE_EMACS=-style names its
  stricter =[A-Z]+= misses.

** elate, and the one idea to take from it

=elate= is an external CLI for driving sandboxed Emacs sessions from JSON
scenarios. The technique to take, independent of the tool: *make the system
under test its own oracle.* Each op types a shell command, applies an Evil edit
over the PTY, presses RET, and asserts on *the shell's output* — the shell proves
the edit landed, so there is no need to model where point should be or what the
grid should contain. 26 ops × 4 shells.

Two supporting ideas: *=expect: "fail"= for known-broken cells*, so a regression
elsewhere still shows red and a future fix shows *XPASS* — and XPASS fails the
run, so a silently-fixed bug cannot stay mislabelled. And *suites targeted at a
surface the main matrix structurally cannot reach*, each README section *naming
the bug the suite was written for* (the boundary suites exist because the
operator matrix runs on bash, which has no autosuggestion or right prompt, so it
never exercises the colour-based input-end detection).

* 10. Leftovers worth a line each

Things no other axis covers:

- *=symbols.map=* — *withdrawn, and the reason is worth more than the item was.*
  The premise was that cooked's =crate-type = ["cdylib", "rlib"]= exports Rust
  symbols that could collide with another loaded module. It does not:
  =nm -D --defined-only target/release/libcooked.so= lists =emacs_module_init=
  and =plugin_is_GPL_compatible= and nothing else, and every other dynamic
  symbol is an import. The =rlib= is a static archive and contributes no dynamic
  exports at all.

  Nor could a =-C link-arg=-Wl,--version-script== have narrowed it. rustc builds
  a cdylib's export list itself from the =#[unsafe(no_mangle)]= items and passes
  it to the linker *as a version script of its own*; ld unions the scripts it is
  given, and an explicit =global= beats a wildcard =local=. Reproduced with a
  deliberate =cooked_probe_symbol=, which is exported identically with and
  without a =symbols.map= naming only the two Emacs symbols and =local: *;= —
  =cargo rustc -- --print link-args= shows both scripts on the command line,
  rustc's first. The script would have been decoration that looked like a
  guarantee. What actually holds the line is rustc's own list plus the
  =unreachable_pub= lint: a new export takes a new =no_mangle= to write.
- *Terminfo round-trip verification.* ghostel's =make regen-terminfo= handles
  the BSD-hashed-dir vs Linux layout difference *and then verifies the result
  round-trips through =infocmp=, failing loudly if not*. cooked's =terminfo=
  target does the dual-spelling dance more neatly (a hex-printf loop) but has
  *no verification*. One line closes a real hole.
- *Picker annotations.* =ghostel-list-buffers= uses =read-buffer= with an
  =annotation-function= showing each terminal's title, capped at a width custom.
  Solves "which of =*cooked*=, =*cooked*<2>=, =*cooked*<3>= is the build?".
  cooked has no buffer picker at all. Their README documents the marginalia
  collision (marginalia replaces annotations for the whole =buffer= category)
  and gives a 10-line wrapper. Cheap and immediately useful — and it wants
  =cooked--title= made public, which is a one-liner. Note cooked has a *title
  stack* ghostel lacks (=cooked-osc.el:104=, limit 8, with an underflowing pop
  correctly treated as the child's bug).
- *A public Lisp API.* =ghostel-create=, =ghostel-exec=, =ghostel-buffer-list=,
  =ghostel-project-buffer-list=, =ghostel-send-string=, =ghostel-send-key=, plus
  a =ghostel-identity= alist on the buffer for later lookup by whatever created
  it. =ghostel-send-key "up" "shift,ctrl"= goes through the encoder and respects
  the current terminal mode. cooked has the send primitives internally but no
  create/list/exec surface. The README names the audience: "agent integrations,
  custom keymaps."
- *=ghostel-sync-theme=* — re-syncs the palette after a theme change; pairs with
  the unsolicited =CSI ?997= push in §8. The unsolicited half is the interesting
  bit: it lets a TUI follow your Emacs theme live.
- *=tools/agent-output.sh= / =scrolling-agent-output.sh=* — synthetic
  coding-agent output generators (spinners, DEC 2026 synchronized updates,
  coloured status lines) with =LINES=N=, =DELAY=S=, =SYNC=0=, =NO_COLOR=1= knobs,
  written to stress bottom-anchoring. *Directly relevant to the scroll-ceiling
  work*, and note they are =LINES=N=-bounded by default rather than infinite —
  the self-limiting-load-generator discipline already learned here the hard way.
- *=ghostel-bold-color=* — nil / =bright= / =#RRGGBB=, matching Ghostty's option.
  Small, and the kind of thing users ask for.

** Documentation practices

ghostel ships a 129 KB README.org with texinfo export headers and generated
command/concept indices, a 168 KB Keep-a-Changelog =CHANGELOG.md=, a separate
short =README.md=, six badges, a themed HTML export to Pages, and
=src/AGENTS.md= + =src/CLAUDE.md= (*byte-identical duplicates*).

Two things genuinely pay for a solo project:

1. *A CHANGELOG kept at ghostel's granularity.* The value is not the format —
   it is that entries are 3–8 sentences explaining the mechanism and the reason
   ("bash 4.4+ emits the marker from =PS0=; older bash keeps a DEBUG-trap
   adapter armed once per prompt cycle"). cooked keeps that reasoning in code
   comments, which is better *placed* but not chronological, so it cannot answer
   "when did this change and what did it replace." One =CHANGELOG.md=, entries
   written at commit time.
2. *One =AGENTS.md= for the Rust side.* ghostel's is 4.5 KB of Zig rules where
   every rule is a mistake someone made: the renderer owns dirty-flag mutation
   and nothing else may touch it; never =catch {}=; =callconv(.c)= signatures are
   a fixed ABI contract; format strings are Emacs syntax not Zig syntax; after
   editing any =.zig=, build must pass then =zig fmt=. cooked has the same class
   of structural invariant — the =unreachable_pub= discipline, the
   rename-not-overwrite module rule currently living as a 15-line Makefile
   comment, the wire-format-stated-in-three-places problem
   =cooked-tests-bench.el= guards. *Write one; do not duplicate it as
   =CLAUDE.md=* — symlink if a tool demands the name.

** Does ghostel argue for merging any of cooked's layers?

*No — zero merges recommended.* But the reasoning matters, because the honest
answer is not "cooked's split is vindicated", it is "ghostel offers no argument
either way, and looking for one surfaced a seam of cooked's that is misplaced on
cooked's own rule."

A 5581-line core is the *absence* of a dependency rule, not an argument against
having one. ghostel's groupings are topical (links, shell, kitty, compile) where
cooked's are directional; when the two disagree, cooked's axis is the stronger
one, because a topic can be split across a dependency boundary without harm
while a dependency cycle cannot. Three specific comparisons:

*** =cooked-link= / =cooked-file-link= — the one real finding

ghostel keeps OSC 8 hyperlinks *and* heuristic URL/file detection in one 865-line
=ghostel-links.el=. cooked splits them across a tier boundary: =cooked-link.el=
in the *base layer*, =cooked-file-link.el= as an *optional layer* above
=cooked.el=. The split is right — the file layer is =require=-to-enable and "the
file being loaded /is/ the feature being on" — but it strains in two places that
are worth fixing before the §6 work lands on top of them:

1. *=cooked-link.el= asks questions upward.* It carries four
   =declare-function='s: =cooked--suspended-p=, =cooked--child-owns-keyboard-p=,
   =cooked-mouse-event= and =cooked-send-key= — and the first two are
   *input-ownership policy questions*, which is exactly what the base layer's
   stated rule forbids. The link layer is deciding whether a click belongs to the
   child. That decision belongs where input ownership already lives
   (=cooked-keys.el= / =cooked-mode.el=), reached from below by a notification or
   a function slot rather than by a declaration.
2. *The base layer arbitrates a concept only the optional layer produces.*
   =cooked-link--claimed-p= encodes the precedence OSC 8 > goto-addr > *guessed
   shape* — but "guessed shape" is =cooked-file-link='s output, so the base layer
   names a category that does not exist unless an upper layer is loaded. It works,
   and it is better than ghostel's arbitration spread across four functions; but
   the ordering should be data the layers contribute to rather than a constant in
   the bottom one.

Both strains are load-bearing for §6: the thing-at-point providers (ROADMAP §3)
*must be installed together* — =url= from =cooked-link=, =filename= /
=existing-filename= from =cooked-file-link= — which means the installation point
straddles the tier boundary and belongs in =cooked-mode.el='s setup, with each
layer contributing its own provider.

*** The shell story, spread across five files

ghostel puts directory tracking, prompt navigation, history, imenu and remote
setup in one =ghostel-shell.el=. cooked spreads the same surface across
=cooked-osc= (OSC 7 and 133 dispatch), =cooked-command= (the records),
=cooked-mode-line=, =cooked-shell-integration= (snippet delivery) and
=cooked-shell-completion= (optional) — soon six with =cooked-history=. *Do not
merge.* Each of those five sits at a different tier for a reason that survives
inspection: the records are base because the drain calls them directly, the
snippet delivery depends on =cooked-completion= for the feature list, and the
completion layer is optional because it is a wire protocol the user opts into.
Merging on topic would create exactly the four =declare-function='s downward that
=DESIGN.md= says =cooked-command.el='s placement exists to avoid.

*** Faces and the palette

ghostel's =ghostel-faces.el= both defines the colour faces and is the source the
core's OSC 4 replies are seeded from. cooked's =cooked-face.el= is already base
tier, so the §8 OSC 4 gap needs no re-layering — the values are reachable from
where the reply has to be built. Nothing to change.

- *Only four new seams*, because the existing twelve hooks already carry the
  deferred-detection, selection-protection and command-finished work.

* 12. Damage: who keeps updates narrow

ghostel advertises this in three places — "Incremental redraw — unchanged rows
are skipped" (=README.org:863=), "libghostty's row dirtiness plus cursor tracking
to update only the rows that need to change" (=:2344=) — and its own measurement
puts the per-row dirty branch at *8–13× faster than full mode*
(=CHANGELOG.md:2167=).

*The advertisement is substantially accurate, with three material omissions.*
"Unchanged rows are skipped" is true of *retransmission* but not of *traversal* —
the renderer walks every active row with Emacs funcalls on every redraw whether
anything is dirty or not (=Renderer.zig:938-978=). libghostty's dirty bit is a
*page* flag OR'd with the row flag (=PageList.zig:6259-6262=), and several hot
paths set the page flag, so "row dirtiness" silently degrades to whole-viewport
dirtiness. And it does not extend to images at all.

** The unit, and the one thing neither ghostel nor libghostty has

*cooked*: a per-row =Vec<bool>= (=screen.rs:179=) set through =Screen::edit=
(=:377=), which marks a row dirty *only if the writer reports the cells now read
differently*. =Row::set=, =fill_run=, =fill= and =erase_all= all answer that
question (=cell.rs:821=, =:849=, =:916=, =:996=). The engineering around it is as
valuable as the mechanism: =fill_run= does the comparison as a separate pass
ahead of the stores because folding them measured a *24% throughput loss*
(=:855-860=), and =Row::clear= deliberately *declines* to answer because on the
scroll path the scan measured *22%* for an answer that path throws away
(=:970-974=). The contract is written as a prohibition — "It is not a general
equality check on the row, and must not become one" (=screen.rs:349-373=) — with
the unconditional-=touch= paths enumerated by name.

*ghostel*: two layers. libghostty's per-row plus per-page =dirty= booleans, with
=Pin.isDirty()= = =page.dirty or row.dirty=; then ghostel's own
=Renderer.isRowDirty= (=:905-915=), which ORs in the old and new cursor rows, and
=render=, which merges *contiguous* dirty rows into one =SpanContent=. Layer 2 is
strictly additive on the dirty set and subtractive on the Emacs-call count; it
cannot narrow a page flag back to rows.

*Nothing in ghostel or libghostty compares content anywhere.* A print marks the
row dirty on the strength of having printed.

** Scroll is where the models genuinely differ

ghostel wins the single most common operation a terminal performs, decisively and
without a scroll opcode on the wire: =index= at the region bottom grows the
pagelist, =active_pin= slides, and the scroll is expressed as *the buffer already
being right*. 2 rows against cooked's 25 — ~12× narrower on damage, ~4× on bytes.

But it only works where =no_scrollback == false= and the region is the full screen
with =top == 0=. Every other scroll shape hits a =page.dirty = true= path and,
because =Pin.isDirty= ORs the page flag, degrades to a *whole-viewport* repaint —
*worse* than cooked, whose =touch_range= at least confines damage to the scroll
region. So =vim=, =less=, and any TUI with a DECSTBM status region get cooked's
behaviour or worse.

(Correction to an earlier guess: =insert-forward= is not a scroll optimisation. It
is programmatic-insertion forwarding, and *deletions are repaired by a full
redraw* — a wholesale trigger, not a scroll path.)

The image row is ~100–2000× and, unlike the others, is not a granularity trade —
it is an absent cache.

** The finding that matters most for cooked

*cooked's per-row block granularity is a Lisp-side choice, not a wire
constraint.* Three facts establish it: =drain_damage= returns *ascending*
indices; =Update::scrolled_rows= already proves one =Block= can hold many rows
with a correct per-row =RowSpan= table (=src/lib.rs:988-993=, =:1000-1035=); and
=Block= offsets are =u32= precisely so a multi-row block can exceed 65536
characters (=:906-916=).

So *a full-screen repaint could go from 24 inserts + 24 delete-regions to 1 + 1
with no protocol change*, reusing =RowSpan= for the row-boundary bookkeeping
=cooked--render-rows= needs for =cooked--guard-row-width= and
=cooked-row-rendered-functions=. That is §7's item 2 with the machinery already
built and exercised on the scrollback path.

One hazard to avoid while copying: ghostel's span breaks only on a *clean row or
page boundary*, so the coalescer faithfully amplifies the page-granularity false
positive into one giant reinsert — and =flushSpan= does =delete-region= *then*
=insert=, destroying every marker and overlay anchored in the viewport. Coalesce
runs of *genuinely* damaged rows, not runs of not-known-clean ones.

** Correctness

ghostel has *a real self-oracle*: =test_full_redraw_does_not_change_buffer_content=
— random write/resize/redraw sequences, incremental render, snapshot, force full
render, snapshot, assert equal. It is the single best thing in either repo on this
axis.

*Its gap: the snapshot is =buffer-substring-no-properties=.* Text only. A missed
=style_id= change — a stale face over correct characters — passes. Given that
=CellPropKey= is a hand-rolled four-field subset of the real style and that run
breaks depend on it, that is the likeliest class of miss and the oracle is blind
to it. The pin's cost is visible: two upstream fixes for exactly this
(=eb722cb26= spacer head, =9313d580c= stale cursor style after scroll clear, the
latter "found via fuzzing") are in =3c1ef5b32= and not in ghostel's =ab0b9da9e=.

cooked's defences are structural rather than a property: the written prohibition,
=Row::runs_to_reference= as a deliberately independent formulation checked
against the fast path ("an optimisation there needs something to be *equivalent
to*, not merely a suite that happened to keep passing"), direct false-positive
tests (=rewriting_a_row_with_what_it_already_says_damages_nothing=),
=cooked--check-seam=, and =cooked-refresh= as the way back.

*The analogous invariant, stated precisely* — and it is strictly stronger than
ghostel's because it covers properties:

#+begin_quote
For any byte stream /S/ and any partition of /S/ into feed chunks with a drain
after each: the buffer produced by applying those drains, restricted to the
screen region, must equal the buffer produced by feeding all of /S/, then
=touch_all()=, then one drain — *including the =face=, =cooked-deco= and link-id
text properties*.
#+end_quote

The Rust half needs no Emacs at all: feed chunked, accumulate the deltas' rows
into a shadow =Vec<Vec<Run>>=, then =touch_all= + drain and compare =Run= vectors
elementwise. That catches a writer returning =false= when something did change —
cooked's exact analogue of a missed dirty bit, and the thing its whole
performance story rests on. This is §9's item 1 with the invariant spelled out.

** Verdict: narrow in different places, and it traces to where each put the scroll

| Workload                                        | Narrower  | Margin                                                                        |
|-------------------------------------------------+-----------+-------------------------------------------------------------------------------|
| bare cursor motion (=vim= =hjkl=, readline nav) | *cooked*  | 2 rows → 0                                                                   |
| identical repaint (spinner, prompt rewrite)     | *cooked*  | 1–24 rows → 0, *and no wake at all*                                          |
| SGR/OSC/mode-only traffic                       | *cooked*  | 0 either way, but ghostel pays 4N funcalls                                    |
| one-line scroll, primary, no region             | *ghostel* | 25 rows → 2                                                                  |
| sustained flood                                 | tie       | both get one big insert, by different routes                                  |
| full-screen repaint                             | split     | ghostel on insert count (24→1); cooked on bytes and on box-drawing/CJK cells |
| scroll-region or alt-screen scroll              | *cooked*  | ghostel degrades to whole viewport                                            |
| resize, reflow, alt enter/leave                 | *cooked*  | ghostel re-materialises the whole scrollback                                  |
| any frame with an image                         | *cooked*  | ~100–2000× on payload                                                         |

cooked kept the grid authoritative and hands rows to Emacs as text on their way
out, which makes scrollback handover, reflow, the seam and image identity all
exactly expressible — and makes a scroll "every row in the region changed",
because after a =rotate_left= every index genuinely does hold different text.
ghostel let the pagelist *be* the scrollback and mirrors it into the buffer,
which makes the common scroll free and makes everything perturbing the pagelist's
identity an =erase-buffer=.

*On aggregate cooked is ahead* — on identical-frame suppression (which no amount
of dirty-bit precision substitutes for), the image cache, the wake gate, and the
absence of six wholesale triggers. But a session that is mostly =tail -f= at one
line per frame is measurably better served by ghostel's model, and that is not a
rare session. Items §7-2 and §12's scroll note are what close it.

* 13. Elisp or Rust: does ghostel change the calculus?

Asked specifically of =cooked-keys.el= against ghostel's Zig =encodeKey=. The
answer generalises, and it is not the one the file sizes suggest.

** The pattern: ghostel's misplacements are all "native code calling Emacs back"

Every place ghostel moved work into the module *and kept asking Emacs questions
from there*, it came out slower or driftier than cooked's Lisp equivalent:

| What ghostel moved native  | What it cost                                                                                                                        |
|----------------------------+-------------------------------------------------------------------------------------------------------------------------------------|
| key encoding (=encodeKey=) | needed a *second*, hand-written Elisp CSI table (=ghostel--raw-key-sequence=) shadowing the Zig one — free to drift                |
| property application       | up to 6 =put-text-property= funcalls per run, and *no face cache at all*                                                            |
| the row walk               | =eobp=/=point=/=forward-line=/=point= per row, clean or dirty — ~180 funcalls on a 45-row screen with one dirty row                |
| glyph metrics              | =composition-get-gstring= / =font-at= funcalls per cluster, from Zig                                                                |
| image placement            | full payload re-emitted per placement per redraw                                                                                    |
| marker save/restore        | correct, but the transform is cheap to compute *in Lisp*, where =cooked--render-rows= already knows =(old-start, old-len, new-len)= |

Against cooked's rule, which is the same rule stated positively: *compute a
compact description in Rust, interpret it in Lisp, cross once per frame.* 22-byte
style records walked with =aref=; run-length deco; =Run::cols= carried rather
than measured; one =cooked--drain= per frame against ghostel's 4N+ funcalls.

So the calculus ghostel clarifies is not "which language is faster." It is:

#+begin_quote
*Move it to Rust when the answer is a pure function of bytes or grid state and
the result is compact. Keep it in Lisp when producing the answer requires asking
Emacs a question* — because from Rust every question is a funcall, and Lisp gets
them for free.
#+end_quote

=Run::cols= is the exception that proves the rule. cooked moved *measurement*
into Rust — but only because the answer was a by-product of work Rust was already
doing over a grid it owns. It asked Emacs nothing. Font metrics, window geometry,
face resolution and buffer positions are the opposite shape, and all four are
places ghostel calls back out of Zig.

** So: no, do not move =cooked-keys.el=

ghostel is the *counter-example*, not the argument. It moved key encoding native
and still needed an Elisp table, because the translation from an Emacs key event
to =(key, mods, text)= is itself Emacs-shaped work. Moving cooked's encoder would
mean either passing a structured key description across the boundary — which *is*
the translation, so nothing has moved — or re-deriving Emacs' key semantics in
Rust. Meanwhile cooked's single derived table (=cooked--key-encodings=, which
yields both the modified and unmodified spelling of every key) replaced five
hand-maintained parallel tables, and is *why* cooked has modifyOtherKeys, 19
keypad capabilities and per-program overrides where ghostel has none.

Note cooked *already* splits this correctly: the core owns the negotiated kitty
flags (=src/emu/term/state.rs=, the push/pop/set stack in =csi.rs:437=), Lisp
owns the encoding. The §4 gap — bits 2/4/8/16 tracked but never changing the
encoding, while =CSI ? u= answers with flags cooked does not honour — is a
symptom of Lisp not acting on what the core already knows. *The fix is to expose
the flags usefully, not to move the encoder.*

** What ghostel does newly justify moving

*Into Rust, two things, both because the work is parsing and the result is
packed:*

1. *The comint stream filter* (§1) — a second =Perform= impl. And here ghostel's
   instinct is right on the wrong side: =style_face.buildFacePlist= shared
   between its renderer and its comint filter is exactly the "one SGR→face
   mapping" idea, executed by calling Emacs from Zig. cooked's version is to
   factor the =set_attribute= arm out of =term/csi.rs= so grid and stream share
   it *in Rust*, and let the existing packed-record path carry the result.
2. *Damage-row coalescing* (§12) — Rust already knows the runs, and =RowSpan=
   already exists.

*Out of Rust into Lisp: nothing.* No survey found work in cooked's core that
would be better placed in Lisp.

*And one thing that looks like a move and is not*: the glyph metrics cache (§2).
The *measurement* must be Lisp, because =font-at= is an Emacs question. The
*cache* should also be Lisp — hung off =cooked--wrap-cache=, which is already
stamped on font, =face-remapping-alist= and geometry, and already thrown away
wholesale when the stamp moves. ghostel put its cache in Zig and gets a weaker
invalidation for it (default-font change only, with =page_serial=-stale entries
never pruned). Borrow the *key shape*, not the side.

* Appendix: things not to copy

- *ConPTY/Windows* — no termios on a pseudoconsole, so =Mode::{Cooked,Raw,Secret}=
  cannot exist there. Shipping it means shipping a build where the flagship
  feature silently does not work.
- *=desktop= registration* — ghostel's four-branch skip list plus a
  =run-at-time 0= shield that undoes desktop's own replay is the evidence
  cooked's refusal is right.
- *=ghostel-compile.el= wholesale* — =cooked-next-error.el= is the better answer
  and covers every command, not just ones launched through =compile=.
- *Conditional =font-lock-face= swapping* — =cooked-process.el:350= already has
  the better unconditional answer.
- *Passing CR/BS through to =comint-carriage-motion=* — cooked documented why
  this is wrong before ghostel shipped it.
- *A second hand-written key table in Lisp shadowing the core encoder*
  (=ghostel--raw-key-sequence=) — cooked's single derived table is the reason it
  does not have five parallel tables to keep in sync.
- *=create-image= per placement per redraw*, and re-emitting images generally —
  it buys ghostel its row-range property shape but costs it two
  eviction-artifact repair passes.
- *Mode 2026 without a deadline* — ghostel's redraw returns early whenever the
  mode is set, with no timeout, so a child that never resets it freezes the
  display. cooked's =SYNC_TIMEOUT= is the correct shape.
- *An eval channel that allowlists names* — =ghostel_cmd find-file /ssh:host:/path=
  from any =cat= of a hostile file, on by default.
- *Python + Hypothesis + a JSON-lines protocol as the first property-testing
  implementation* — the highest-value property for cooked needs no Emacs at all.
- *Reporting means as the headline figure* — the one methodological choice in
  ghostel's bench that is actively wrong for a load-sensitive suite.
- *The texinfo/Pages export pipeline, the dual README.md/README.org, six badges,
  and melpazoid targets before a MELPA submission* — ceremony for a solo repo.
- *=AGENTS.md= duplicated as =CLAUDE.md=* — byte-identical files that diverge
  the first time one is edited.
- *A macOS-only absolute path as an artifact-directory default* — if the
  artifact-writing idea gets ported, default it to the repo's scratch dir.
